# 链接预测 · 知识辐射网络

> 来源：面试备考知识整理，整理自63个概念页的交叉关联
> 整理日期：2026-07-04
> 主题：KG领域最核心的母任务，所有其他KG概念都是它的变种或应用

---

## 一、核心定义

链接预测就是：给定知识图谱里的头实体 h 和关系 r，预测最可能的尾实体 t；或者给定头 h 和尾 t，预测它们之间最可能有什么关系 r。本质上就是补全图谱里缺失的边。

---

## 二、四大实现路径分支

### 2.1 表示学习分支
- 核心：TransE 平移假设 h + r ≈ t
- 变种：TransH / TransR / RotatE，解决对称/反对称/一对多关系问题
- 本质问题：嵌入不可解释，工业界很少真用

### 2.2 规则学习分支
- 核心：AMIE算法挖掘Horn规则，如「A的父亲是B，B的父亲是C → A的祖父是C」
- 优点：100%可解释，泛化性好
- 缺点：覆盖率低，长尾关系挖不到
- 大模型普及后的变化：LLM天生就会写规则，这类方法的研究明显减少

### 2.3 GNN分支
- 核心：消息传递范式，每个节点聚合邻居信息更新表示
- RGCN：专门为异构图设计，不同关系用不同权重矩阵
- 工业落地痛点：训练慢、推理慢、小图效果好大图提升有限

### 2.4 大模型分支（2024年后的新范式）
- 路径1：直接让LLM做预测——"乔布斯和苹果公司是什么关系？"
- 路径2：让LLM做NLI验证，不做预测——"根据原文'乔布斯创立了苹果'，请问三元组(乔布斯,创立,苹果)是否成立？"
- 我的选择：TripleChecker走NLI验证路线，放弃预测只做验证

## 三、五大变种任务（链接预测换马甲）

| 任务名称 | 和链接预测的关系 | 核心差异 |
|---|---|---|
| 知识图谱补全 KGC | 完全是一回事，别名 | 无 |
| 实体对齐 | 跨图谱的链接预测——预测两个不同KG的实体是不是同一个 | 多源异构 |
| 实体消歧 | 单文档内的链接预测——预测"苹果"链接到哪个实体 | 单文档上下文 |
| 三元组分类 | 链接预测的二分类版本——不问哪个对，只问这个对不对 | 二分类简化 |
| 冲突检测 | 反向链接预测——预测两个三元组是不是矛盾 | 负向判断 |

## 四、四大应用场景

### 4.1 GraphRAG场景
- 传统用法：抽实体 → 链接预测找相关实体 → 生成答案
- 我的改造：EvidenceFirst不用预测，直接BFS搜路径，搜得到就是有，搜不到就是没有

### 4.2 知识融合场景
- 多源融合本质就是跨源链接预测
- 我的实践：先TripleChecker过滤 → 规则对齐明确实体 → LLM验证模糊项 → 低置信度送人工

### 4.3 垂直领域场景（以FinGraph为例）
- 财务场景链接预测是地狱难度：(万科,营收,100亿) vs (万科,净利润,10亿) 差一个字差10倍
- 核心洞察：垂直领域链接预测本质是本体设计问题，不是模型问题

### 4.4 QA问答场景
- 多跳问答本质就是在图上做多次链接预测
- 核心问题：跳数越多，误差累积越严重

## 五、评价指标与陷阱

| 指标 | 含义 | 工业界真实用法 |
|---|---|---|
| MRR | 正确答案排名倒数的平均 | 学术圈喜欢，工业界不怎么关心 |
| Hits@1/3/10 | 正确答案出现在前K名的比例 | 只看Hits@1，排第2和排第100没有区别 |
| AUC | ROC曲线下面积 | 二分类任务常用，容易被负采样作弊 |

最重要的行业洞察：90%的KGC论文负采样都是随机替换实体，太简单了，Hits@1看起来90%多，一到真实场景就崩。真正靠谱的负样本应该是LLM生成的高迷惑性幻觉三元组。

## 六、我的三个实践改造

### 6.1 TripleChecker：从排序 → 二分类
- 传统：给(h, r) → 排10000个t
- 我：给(h, r, t) → 只输出对/不对/不确定
- 收益：准确率从70%升到92%，每个判断都有置信度

### 6.2 EvidenceFirst：从预测 → 验证
- 传统：链接预测猜"哪些实体相关"
- 我：BFS搜"哪些实体真的连通"
- 收益：有路径的100%正确，没路径的不瞎编

### 6.3 Graph Fusion：从单源 → 多源对齐
- 传统：算嵌入相似度，高的就对齐
- 我：分层过滤+验证，人工审核量减少70%，准确率从85%升到93%

## 七、跨领域知识共鸣

### 和上下文学习 ICL
链接预测基于观察泛化 → ICL基于示例泛化 → 本质都是从已知推未知

### 和思维链 CoT
链接预测多跳推理误差累积 → CoT多步推理误差累积 → 本质都是长链不可靠

### 和KV Cache
链接预测把验证过的边缓存进KG → KV Cache把算过的键值缓存下来 → 本质都是用空间换时间，用确定性换速度

### 和提示注入
坏的链接预测把幻觉伪装成边 → 提示注入把恶意指令伪装成数据 → 本质都是输入流和控制流没有隔离

## 八、面试回答框架

开口先定义 → 然后说"但我做了三个项目后发现，学术和工业的链接预测根本是两个问题" → 分三点展开（目标函数、可用信息、错误代价） → 讲我的三个实践改造 → 最后拔高到元规律："现在LLM太能无中生有了，我们不需要另一个模型来生更多边，我们需要一个模型来帮我们删掉错的边。"
