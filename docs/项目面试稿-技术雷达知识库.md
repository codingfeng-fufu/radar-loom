# 技术雷达 / 个人知识外脑

## 一句话介绍

技术雷达是我独立设计并持续维护的本地知识工程系统：它把原始材料摄入、结构化建页、全文搜索、动态分类、知识图谱、质量检查和 Claude Code 协作组织成一条可回放工作流。

## 30 秒回答

一次性的对话和笔记很容易丢失，也很难知道来源和版本。我用 Markdown 作为可审计的数据层，用 Git 记录变化，再开发索引、分类、图谱和健康检查脚本，把论文、实验和 Agent 开发资料编译成可搜索、可交叉引用的知识库。系统还接入本地 Web 操作台和 Claude Code：Agent 可以创建知识页、查重、刷新索引、查看图谱并执行安全维护。当前有 134 个概念页、5 个项目页、8 个工程面试页，知识图谱 148 个节点、855 条边，断链为 0。

## 1. 项目背景

### 为什么做

- 学习和研究材料分散在对话、PDF、代码仓库和临时笔记中。
- 新知识容易重复建页，旧页面又缺少来源和交叉引用。
- 让 Agent 直接修改知识库存在误写、越权命令和索引不同步风险。

### 目标

建立一个本地优先、可审计、可持续维护的知识系统，让原始证据、结构化页面、索引、图谱和 Git 历史保持一致。

## 2. 系统整体架构

## 2A. 谁使用、谁买单

直接用户是研发人员、研究人员和技术团队；个人可以为长期知识管理订阅，企业则可能由研发效能或知识管理部门买单。购买理由是减少重复调研、新人上手和知识丢失成本，并保留来源、版本和组织经验。当前系统是单用户本地工具，企业化需要补充多租户、权限、协作和托管服务。

## 3. 我的个人贡献

- 设计知识库目录、页面协议、frontmatter、来源和双链约定。
- 开发索引、动态分类、图谱渲染和健康检查脚本。
- 搭建本地 Web 操作台、Markdown Viewer、Cytoscape 图谱和刷新 API。
- 设计 Claude Code 的创建知识页、捕获想法、检索和安全应用流程。
- 处理 iframe 通信、刷新回执、草稿保留、图谱重建和服务端口边界等工程问题。

## 4. 核心技术实现

### 4.1 Markdown + frontmatter 作为数据层

页面不是随意笔记，而是带摘要、来源、信度、标签和角色字段的结构化 Markdown。`raw/` 保留不可变原始证据，`pages/` 保存可维护页面，Git 提交记录每次变更，页面之间用双链连接。

### 4.2 索引、分类与图谱的派生构建

`build_index.py` 从 frontmatter 生成检索索引；`taxonomy_cli.py` 负责增量同步、全局重组和校验；`render_graph.py` 生成关系图和 JSON 数据。分类失败时保留上一版有效快照，不发布部分结果，避免一次模型异常破坏整个导航结构。

### 4.3 健康检查与发布边界

`check_health.py` 检查 frontmatter、双链、来源存在性、摘要、索引同步、公式定界符和图谱一致性。知识库的质量不只靠人工浏览，而是把结构错误变成可自动发现的检查项。

### 4.4 Claude Code 与 Web 操作台集成

操作台提供 Markdown Viewer、图谱、索引和 Claude 会话。外层操作台和 iframe 通过带版本的 `postMessage` 传递当前文件、图谱状态和刷新完成回执；Claude 侧使用固定工作目录和安全写入流程，不接受前端传入任意 shell。

## 5. 最难的问题

### 难题一：知识页、索引和图谱如何保持一致

页面更新后必须同时刷新索引、分类和图谱，因此采用“原始页 -> 派生构建 -> 健康检查 -> Git 提交”的闭环，并保留分类快照和失败回滚边界。

### 难题二：刷新成功但前端仍显示超时

一次故障中后端刷新已返回 200，但 iframe 没有返回 `kb-refresh-result` 回执。修复时补齐受信 origin/source 校验和完成回执，同时在刷新列表和图谱时保留当前选中项并销毁旧 Cytoscape 实例。

### 难题三：Agent 写入的安全边界

Agent 可以提出维护计划，但 safe apply 只执行白名单内的文件写入，不执行任意 shell；语义审计默认只生成建议，不直接修改知识库。这样把“建议”和“实际变更”分开。

### 难题四：多个本地服务端口被误用

WebUI 和知识库 Viewer 使用不同端口。发生进程误启动后，通过 PID、日志和端口职责定位具体错误进程，只恢复受影响服务，再分别验证操作台、原文和 Claude 输入框，避免粗暴终止全部进程。

1. 搜索一个 Agent 或 RAG 概念页面。
2. 展示来源、摘要、双链和相关概念。

## 8. 可能追问

### 为什么不用数据库作为唯一存储？

Markdown + Git 便于 diff、审阅、迁移和离线维护；索引和图谱是可重建的派生物，不把不可逆状态锁在数据库里。

### 如何避免知识重复？

建页前执行标题、别名和语义三层查重，并优先更新已有概念页；健康检查再验证链接和索引是否同步。

### 为什么不让 Agent 直接执行 shell？

知识维护的风险不值得用任意命令换取便利。系统将计划、白名单应用、审计和实际变更分层，减少误写和越权范围。

### 当前限制是什么？

分类和语义查重仍受模型与配额影响，图谱大规模渲染和多人协作不是当前目标，内容质量仍需人工复核。

## 9. 1 分钟总结

技术雷达不是一个文件夹，而是一套把知识当作可维护工程资产的本地系统。我的工作重点是建立数据生命周期和质量边界：原始证据不可变，页面结构统一，索引和图谱可重建，Agent 只能通过受控流程修改，Git 和健康检查负责追溯与验收。
