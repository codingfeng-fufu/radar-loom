# 技术雷达知识库 Web 操作台说明书设计

## 目标

在知识库根目录新增一份长期维护的综合说明书，面向日常使用者和后续维护者，集中说明 Web 操作台的启动、使用、配置、验证、故障排查与安全边界。说明书与部署完成报告分工明确：部署报告记录当时的交付结果，说明书描述当前系统如何使用和维护。

## 交付文件

- 新增：`Web操作台使用与维护说明书.md`
- 修改：`README.md`，增加说明书入口

不修改 WebUI 运行配置、知识库页面内容或现有部署报告。

## 读者与使用场景

说明书同时服务两类读者：

1. 日常使用者：需要快速启动服务、浏览知识库、查看图谱、向 Claude 提问和理解权限模式。
2. 维护者：需要更换火山 Coding Plan 密钥、理解配置隔离、重启服务、查看日志、运行测试并处理常见故障。

## 内容结构

1. 项目定位与系统组成
2. 快速开始，包括启动、停止、重启、状态、日志和访问地址
3. 一体化操作台界面与常用操作
4. Viewer、数学公式与交互式图谱
5. Claude Code 对话、Markdown 渲染和四档权限模式
6. 知识库检索、编辑与增量摄入流程
7. 火山 Coding Plan 专用配置与用户主目录配置隔离
8. 目录、进程、端口和数据流
9. 日常维护、自动化测试与健康检查
10. 常见故障诊断和恢复步骤
11. 安全边界、密钥管理和已知限制
12. 关键文件索引

## 安全要求

- 不记录或展示 API Key、认证 Token 或其他密钥值。
- 只说明密钥文件路径、字段名、权限和替换方式。
- 明确两个服务必须保持绑定 `127.0.0.1`。
- 明确 `dangerously skip permissions` 的作用与风险。
- 不建议把 `runtime.env` 提交到 Git，也不输出其敏感内容。

## 写作要求

- 开头直接给出最常用的启动命令和访问地址。
- 命令使用可直接执行的完整路径。
- 区分“必须执行”“按需执行”和“故障时执行”。
- 说明正常结果和常见失败表现，避免只列命令不解释结果。
- 对现有已知限制只描述实际边界，不虚构尚未实现的能力。
- 与现有 README 保持术语一致，使用“知识库 Viewer”“交互式知识图谱”“Claude Code WebUI”等名称。

## 验收标准

- 说明书覆盖已确认的十二个章节。
- `README.md` 提供清晰入口。
- 启停命令、访问地址、配置路径、端口和测试命令与当前系统一致。
- 文档中不存在实际密钥或 Token。
- Markdown 链接和代码块格式正确。
- `python3 scripts/check_health.py` 通过。
- `git diff --check` 通过。
