# 可演化多继承分类图谱设计

## 1. 目标

技术雷达知识库当前使用 `KG`、`RAG`、`LLM机制`、`可信度`、`多智能体`、`基础`、`评测`、`前沿` 八个固定分类标签。该结构适合初期导航，但不能随知识规模增长自动发现新主题，也预设了现有大类永久处于顶层。

本设计建立一个可自动新增、合并、拆分、升格、降格和改名的分类图谱。页面可属于多个类别，类别可拥有多个上位类别，分类之间还可表达“相关但非包含”关系。分类漂移是允许的，但每次变化必须可解释、可审计、可回滚。

## 2. 设计原则

1. **分类是图，不是固定层数的树**：允许多上位、多归属、平级新根类别和跨领域主题。
2. **现有八类只是初始种子**：它们不享有永久顶层地位，可被重组、合并、拆分或替换。
3. **页面内容与算法分类分离**：自动分类不在每轮全局重组时批量改写页面 frontmatter。
4. **即时反馈，低频全局重组**：建页后立即执行低成本增量归类，昂贵的全局聚类按阈值、周期或手动命令触发。
5. **本地计算为主**：向量、近邻、聚类和图社区发现在本地完成；LLM 仅负责变化类别的命名、定义和边界摘要。
6. **稳定身份，允许语义演化**：类别名称可变，但稳定 ID、别名、重定向和变更事件保证历史可追踪。

## 3. 数据模型

自动分类结果保存为一个可提交、可回滚的注册表 `taxonomy.json`。注册表顶层包含 schema 版本、生成时间、算法版本、参数指纹、类别、页面归属和变更事件。页面向量和中间计算结果保存在 Git 忽略的 `.cache/taxonomy/` 目录。

### 3.1 类别

每个类别包含：

- `id`：不随改名变化的稳定标识；
- `name`：当前显示名称；
- `definition`：该类别的适用边界；
- `status`：`forming`、`stable` 或 `merged`；
- `naming_status`：`ready` 或 `pending`，与类别生命周期状态分离；
- `parents`：零个或多个上位类别 ID；
- `related`：相关但不构成包含的类别 ID；
- `aliases`：历史名称和已合并类别的检索别名；
- `redirect_to`：已合并类别指向的主类别；
- `created_at`、`updated_at` 和 `last_stable_at`；
- `algorithm_version` 和本次计算的参数摘要。

### 3.2 页面归属

每条归属包含：

- 页面的稳定路径；
- 类别 ID；
- `score`：综合归属分数；
- `signals`：语义、双链、项目和人工标签对结果的分项贡献；
- `reason`：面向人的简短归属依据；
- 首次归属和最近确认时间。

页面允许没有动态类别，也允许同时属于多个类别。不为追求覆盖率强行归类。

### 3.3 变更事件

注册表记录新建、改名、合并、拆分、升格、降格、父关系变更和成员大幅变化。事件包含前后 ID、触发依据、算法版本和时间。Git 历史作为完整快照和回滚边界。

## 4. 分类流程

### 4.1 页面表示

从标题、摘要、章节标题和正文分块生成多语言语义向量。文本未变化时通过内容指纹复用向量。默认使用 `sentence-transformers` 加载 `intfloat/multilingual-e5-small`，在 CPU 上运行并缓存模型文件；模型名称可通过配置替换，但替换模型必须改变算法版本并触发全库向量重建。

### 4.2 即时增量分类

每次新建或修改知识页后：

1. 只计算当前变化页面的向量；
2. 计算它与现有类别中心及近邻页面的语义相似度；
3. 叠加双链邻居、项目标签和原有人工标签信号；
4. 写入所有超过阈值的多类别归属；
5. 若当前页与现有类别都不匹配，但它与至少两个已有页面构成高内聚小群组，立即创建 `forming` 类别。

单个离群页面不独立形成类别。增量分类必须在知识页已成功保存后运行，它的失败不能回滚或阻断页面创建。

### 4.3 低频全局重组

全局重组在以下任一条件满足时执行：

- 累计新增或修改 5 个页面；
- 到达每周调度时间；
- 用户手动触发。

全局流程使用 `sklearn.cluster.HDBSCAN` 产生语义密度群组，使用 `networkx.algorithms.community.louvain_communities` 产生双链社区，再根据成员一致性进行融合。所有带随机性的步骤使用配置中的固定随机种子。新群组与旧类别通过成员 Jaccard 重合、类别中心相似度和图结构相似度匹配，以区分延续、新建、合并和拆分。

类别内部具有明显多个群组时自动拆分；类别高度重叠时自动合并；包含与被包含关系足够稳定时建立多上位关系；语义相关但不存在稳定包含时建立 `related` 关系。

### 4.4 命名和定义

LLM 只接收新增或发生实质变化类别的代表页面标题、摘要、主要关键词和相邻类别定义，输出简短、可区分的类别名称与边界。每轮设置最大命名调用数，超出部分延后处理。

命名调用失败时，类别仍然成立，暂时使用代表关键词作为名称并将 `naming_status` 设为 `pending`。上游限流不影响页面归类、聚类和知识库浏览。

## 5. 类别生命周期

- 至少 3 个高内聚页面才能形成 `forming` 类别；
- 类别连续两次全局运行仍存在，或成员达到 5 页时，可转为 `stable`；
- 拆分时保留与原类别最匹配的主分支 ID，其他分支获得新 ID；
- 合并时保留一个主 ID，其他 ID 转为别名和重定向；
- 类别名称改变不改变 ID；
- 没有合适上位类别时，允许新类别成为新根；
- 现有八类完成初次迁移后与其他类别遵循同一生命周期规则。

所有阈值存放于独立配置，不散落在算法代码中。每次运行在注册表中记录所使用的参数。

## 6. 用户界面与图谱

交互图谱增加三个视图模式：

1. **知识关系**：保留当前页面节点和双链关系；
2. **分类结构**：显示类别节点以及上位、下位、相关、合并来源关系；
3. **综合视图**：类别作为结构节点，页面与所有归属类别相连。

现有固定八类筛选改为可展开的分类图谱导航。类别详情显示名称、定义、状态、页面数、最近变化、上下位和相关类别。页面详情显示多类别归属、分数和简短依据。

操作台在页面创建后只显示简短状态，例如“已归入 3 个类别”或“形成新类别：Agent 长期记忆”。提供手动全局重组控件，同时保留累计 5 页变更和每周自动触发。分类注册表变化后复用现有图谱动态刷新链路。

## 7. 运行边界与故障处理

- 嵌入模型或聚类不可用时，保留上一版有效 `taxonomy.json`，不发布部分结果；
- 全局重组先写入临时文件，完成 schema、引用、环和重定向校验后原子替换；
- 增量归类失败不影响知识页创建，失败页进入待重试队列；
- LLM 限流只延后命名，不影响本地分类结果；
- 页面删除后，下一次增量检查从归属中删除该页，并评估相关类别是否收缩或消失；
- 所有运行保存日志，但不记录 API 密钥或完整用户凭据。

## 8. 成本与性能

- 文本向量按内容指纹缓存，未变化页面不重复计算；
- 当前规模和可预见的中小规模使用 NumPy 余弦检索，不引入向量数据库；
- 增量分类只检索当前页的近邻和类别中心，不执行全库两两 LLM 比较；
- 日常向量和聚类无付费 API 成本；
- LLM 命名只针对新增或实质变化类别，每轮有可配置调用上限；
- 增量分类在知识页写入后异步运行，不阻塞创建流程。

## 9. 迁移

初次迁移扫描当前所有页面，将八个固定分类创建为种子类别，并把现有标签转换为初始人工信号和归属。项目标签保持为独立维度。

迁移期间不删除页面原有标签。索引与图谱导航切换到分类注册表后，原标签作为历史和人工证据保留。初次全局重组产生的新类别、父关系和多归属必须通过完整校验后一次性发布。

## 10. 验收标准

1. 从现有页面和八类完成首次迁移，不丢失原有归属；
2. 构造跨 `KG` 和 `RAG` 的页面后，页面能同时进入多个类别；
3. 连续新增语义内聚且与旧类别不匹配的页面时，至少 3 页后自动形成 `forming` 类别；
4. 删除验收页后，归属和类别成员数自动收缩；
5. 合并、拆分和改名后，类别 ID、别名、重定向和变更事件可追踪；
6. 嵌入或 LLM 故障时保留上一版有效分类，不影响页面创建与浏览；
7. 分类注册表可确定性重建，重复运行在输入未变化时不产生无意义 Git 差异；
8. 图谱的知识关系、分类结构和综合视图在桌面和移动端均可操作；
9. 页面归属详情能显示分数与信号依据，类别详情能显示生命周期和最近变化；
10. 操作台可手动触发全局重组，累计 5 页变更和每周触发也可正常运行。

## 11. 非目标

- 本阶段不建设通用向量数据库或分布式聚类服务；
- 不强制所有页面必须属于某个动态类别；
- 不要求分类结构长期不变；
- 不将 LLM 作为全库两两相似度判断器；
- 不在全局重组时批量改写知识页正文或 frontmatter。
