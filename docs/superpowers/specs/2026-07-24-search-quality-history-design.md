# 桌面工作台搜索、页面质量与操作历史设计

## 目标

补齐桌面工作台的三个产品体验缺口：统一搜索、客观页面质量可见性、操作历史。三个模块独立验收，共享现有 Viewer、工程面试专区、版本化操作结果和知识库服务。

## 范围与边界

- 统一搜索同时检索普通知识区和工程面试区，但结果按专区分组，两个专区的索引、导航和图谱保持独立。
- 页面质量只展示可由现有文件和脚本客观计算的指标，不引入模型评分、主观等级或外部 API。
- 操作历史只存浏览器本地最近 50 条元数据，不保存 Markdown 正文、Claude 对话正文或文件内容。
- 本轮只面向桌面工作台；移动端保持现有降级布局。

## 统一搜索

外层工作台提供一个搜索入口。初始化时分别加载 `_index.md` 与 `_interview_index.md`，解析为内存索引。匹配字段包括标题、别名、标签、摘要，以及面试页的岗位、难度和知识方向。查询使用 Unicode 小写归一化和空白分词，要求每个词命中至少一个字段；排序优先级为标题前缀、标题包含、别名、标签、摘要，再按专区和标题稳定排序。

结果显示专区、页面类型、标题、摘要和关键标签。普通知识页跳转到现有 Viewer，工程面试页跳转到工程面试专区；搜索结果不合并两个图谱，也不改变现有目录状态。索引加载失败时保留工作台和原有导航，并在搜索面板内显示明确的不可用状态。

## 页面质量

`build_index.py` 为每个页面生成可复用的客观字段；Viewer 在当前页展示紧凑质量摘要，详细内容可展开。指标包括：

- 摘要是否存在且非占位文本；
- 来源 URL 和信度字段是否存在且格式有效；
- 分类标签和项目标签是否存在；
- 出站引用数量、入站引用数量和断链数量；
- 标题、正文、公式、代码块等结构是否可解析；
- 页面是否被健康检查标记为 ERROR/WARN。

缺失数据显示“未检测到”，不推断为通过。全库健康检查仍由现有脚本负责，页面级面板只消费索引和健康结果，不在浏览器扫描整个知识库。

## 操作历史

外层接收现有 `radar-workbench-result-v1` 结果，规范化后写入 `localStorage`。每条记录包含时间、操作类型、状态、来源面板、revision、节点/边统计、保留状态和长度受限的错误摘要。最多保存 50 条，按最新优先；提供状态筛选、单条展开和清空全部历史。存储不可用时退化为当前会话内存，不阻塞操作台。

历史记录不保存 Markdown、Claude 输入输出、绝对文件内容或未经校验的消息字段。刷新页面后恢复历史入口和最近结果；清空操作立即更新界面和本地存储。

## 错误与性能

- 搜索索引缺失或解析失败不影响 Viewer、图谱和 Claude。
- 质量字段不完整时逐项显示未知，不制造成功结论。
- 历史字段全部限长，写入前再次规范化，避免 localStorage 污染和异常消息注入。
- 搜索索引只初始化一次；页面切换只读取当前页质量字段；浏览器不重复执行全库健康检查。

## 验证

- Python：索引生成、质量字段、引用计数和异常页面。
- Node：搜索归一化/排序、质量模型、历史记录规范化和存储上限。
- Playwright：桌面搜索、普通知识页与面试页跳转、质量面板、历史写入/筛选/清空/刷新恢复，以及索引失败降级。
