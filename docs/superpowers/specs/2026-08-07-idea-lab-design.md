# Idea Lab 独立想法实验室设计

## 目标

为技术雷达项目增加一个完全独立的 Idea 记忆与重组模块。它用于快速保存尚未成熟的灵感、记录实际尝试及失败原因，并在未来出现新 Idea 时找出可能补全旧阻塞点的组合机会。

该模块不把失败等同于无效，也不要求 Idea 在录入时已经完整。系统应保留原始表达、尝试过程、仍然有效的部分和重新启动条件，使暂时未成功的想法能够在新条件出现后重新激活。

## 产品边界

Idea Lab 与现有知识库、工程面试和 Paper 阅读相互独立：

| 模块 | 主要对象 | 内容性质 | 质量标准 |
|---|---|---|---|
| 技术知识库 | 概念与项目知识 | 相对稳定 | 来源、信度、事实准确性 |
| 工程面试 | 面试问题与回答 | 面向复习和表达 | 回答边界、岗位与难度 |
| Paper 阅读 | 论文证据与分析 | 以原文为依据 | 引文定位与结论对应 |
| Idea Lab | 灵感、尝试、失败与组合 | 允许不成熟 | 原始表达、过程真实性、关系可追溯 |

Idea Lab 必须满足以下隔离要求：

- 不计入 `pages/` 页面数量。
- 不进入主 `_index.md`、`taxonomy.json` 或 `graph-data.json`。
- 不参加主知识库的分类、核心节点排名和健康检查。
- 使用独立的页面目录、索引、图谱数据、健康检查和 Web 入口。
- 可以引用知识页、工程项目或外部文件，但这些关系只作为外部引用展示。
- 主知识库页面不因 Idea 的创建、状态变化或组合而被自动修改。

## 核心原则

### 原始表达不可覆盖

每条 Idea 必须保存用户最初输入的原话。Claude 可以补充结构化分析，但不得用扩写后的文本替换原始表达。

### 失败是可复用信息

一次尝试未成功后，必须区分：

- 哪个环节失败；
- 哪些假设被否定；
- 哪些部件仍然有效；
- 需要出现什么条件才值得重试。

### 组合创建新记录

多条 Idea 组合时创建一条新的 Idea。原始 Idea 不被覆盖或删除，只增加指向组合结果的关系。

### 文件保持稳定

正式 Idea 页面统一平铺在 `ideas/pages/`，不随状态或主题移动。状态和领域通过元数据生成视图，避免重命名和移动破坏链接与 Git 历史。

### 自动匹配只提供候选

系统可以找出潜在组合，但不能未经用户确认自动合并、改写或改变状态。匹配分数只表示文本和结构信号相符，不表示方案一定可行。

## 信息模型

首版只持久化一种核心对象：Idea 页面。

“问题”“阻塞点”“重新启动条件”“尝试”和“组合”由 Idea 页面中的结构化字段及正文派生，不各自建立独立文件。这能避免多个对象之间的同步、删除和版本一致性问题。

### Idea 标识

每条 Idea 使用稳定 ID：

```text
IDEA-YYYY-NNN
```

- `YYYY` 为创建年份。
- `NNN` 为该年份内三位递增序号，从 `001` 开始。
- ID 一经创建不得修改或复用。
- 文件名格式为 `IDEA-YYYY-NNN 标题.md`。
- 页面引用和组合关系使用 ID，不依赖可变标题。

### 页面元数据

```yaml
---
id: IDEA-2026-001
title: 让知识库自动发现新的知识类别
status: blocked
created: 2026-08-07
updated: 2026-08-07
problem: 既有分类无法覆盖未来不断出现的新方向
domains: [知识管理, 自动分类, 图谱]
blockers:
  - 类别名称缺少稳定性
  - 用户看不出分类形成依据
restart_when:
  - 出现稳定、低成本且可解释的类别命名方法
derived_from: []
combined_into: []
related_ideas: []
external_refs:
  - type: knowledge
    target: 主题模型 LDA
---
```

字段约束：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 稳定唯一标识 |
| `title` | 是 | 可修改的显示标题 |
| `status` | 是 | 当前生命周期状态 |
| `created` | 是 | 首次记录日期 |
| `updated` | 是 | 最近实质修改日期 |
| `problem` | 否 | Idea 想解决的问题；快速记录阶段允许为空 |
| `domains` | 否 | 多值主题领域，不决定文件位置 |
| `blockers` | 否 | 已明确的阻塞点 |
| `restart_when` | 否 | 值得重新尝试的触发条件 |
| `derived_from` | 否 | 当前 Idea 组合自哪些旧 Idea |
| `combined_into` | 否 | 当前 Idea 已被哪些组合 Idea 使用 |
| `related_ideas` | 否 | 有关联但尚不能确定组合关系的 Idea |
| `external_refs` | 否 | 指向知识页、项目、论文或普通 URL 的外部引用 |

所有列表字段缺失时等价于空列表。未知字段由解析器保留，避免后续 schema 扩展时破坏旧页面。

### 页面正文

正式 Idea 页采用以下结构：

```markdown
# Idea 标题

## 原始想法

用户首次记录时的原话。

## 想解决的问题

该想法的触发问题和使用场景。

## 核心设想

当前认为可能有效的机制。

## 当前判断

明确区分已观察事实、假设和个人判断。

## 仍然有效的部分

即使整体尝试失败，仍可复用的判断、机制或组件。

## 尝试记录

### 2026-08-07 · 第一次尝试

**采用方案：**

**实际结果：**

**失败或不足：**

**仍然有效：**

**重新启动条件：**

## 演化记录

- 2026-08-07：首次记录。
```

只有“原始想法”为永久必需正文段落。快速记录时允许其他段落为空或暂不生成；从收件箱整理为正式 Idea 时再补齐适用部分。系统不得生成没有内容的占位章节。

## 生命周期

### 状态定义

| 状态 | 含义 |
|---|---|
| `captured` | 已保存原始灵感，尚未结构化分析 |
| `exploring` | 正在补充背景、推演机制或查找资料 |
| `attempted` | 已经发生至少一次实际尝试，尚未得到明确结论 |
| `blocked` | 方向仍可能成立，但存在明确阻塞点 |
| `dormant` | 当前没有继续条件，保留等待未来变化 |
| `validated` | 已获得实验、原型或实践结果支持 |
| `abandoned` | 已有明确证据或理由决定不再推进 |

### 状态转换

```text
captured -> exploring
captured -> dormant
exploring -> attempted
exploring -> dormant
attempted -> blocked
attempted -> validated
attempted -> abandoned
blocked -> exploring
blocked -> dormant
blocked -> validated
dormant -> exploring
dormant -> abandoned
validated -> exploring
```

- 新建 Idea 默认状态为 `captured`。
- 记录第一次实际尝试后可以进入 `attempted`。
- 只有明确记录阻塞点后才能进入 `blocked`。
- `dormant` 表示当前不推进，不表示 Idea 被否定。
- `abandoned` 必须在正文中记录放弃理由。
- 组合本身不是状态，旧 Idea 可以在任意状态下被组合。
- 已验证 Idea 在新证据出现后允许重新进入 `exploring`。

## 尝试记录

尝试作为 Idea 页面中的追加事件保存，不单独建页。每次尝试至少记录：

1. 日期和简短名称；
2. 实际采用的方案；
3. 可观察结果；
4. 失败、不足或意外；
5. 仍然有效的部分；
6. 可选的重新启动条件。

尝试记录只追加，不重写历史。后来发现早期判断错误时，在新的演化记录中更正，不静默修改旧结论。

## 组合模型

### 候选发现

新 Idea 创建或更新后，系统从以下信号中寻找候选：

1. `problem` 相似度；
2. 新 Idea 的机制是否匹配旧 Idea 的 `blockers`；
3. 新 Idea 是否满足旧 Idea 的 `restart_when`；
4. `domains` 重叠程度；
5. 正文语义相似度；
6. 是否引用相同知识页、论文或项目；
7. 是否出现互补词组，如“缺少 X”与“提供 X”。

首版使用本地规则、关键词和已有向量能力，不因候选匹配额外调用 Claude API。没有向量依赖时降级到元数据和文本匹配。

### 候选展示

每条候选必须显示：

- 候选 Idea 的 ID 和标题；
- 匹配的具体旧阻塞点或重新启动条件；
- 当前 Idea 中与之对应的文本；
- 匹配信号摘要；
- 非概率性质的匹配分数。

界面不得只显示一个没有解释的百分比。

### 创建组合 Idea

用户确认组合后生成新草稿：

```yaml
derived_from:
  - IDEA-2026-001
  - IDEA-2026-009
```

组合页正文必须说明：

- 从每条来源 Idea 继承了什么；
- 哪个阻塞点被哪项新能力补全；
- 组合后的完整机制；
- 组合产生的新风险；
- 最小验证方式。

组合页保存成功后，系统在来源页面的 `combined_into` 中追加新 ID。该双向更新必须作为一个操作完成；任一页面写入失败时不得留下单向关系。

## 目录结构

```text
ideas/
├── README.md
├── inbox/
├── pages/
├── assets/
├── templates/
│   └── idea.md
├── data/
│   ├── idea-index.json
│   └── idea-graph-data.json
├── scripts/
│   ├── idea_common.py
│   ├── new_idea.py
│   ├── build_idea_index.py
│   ├── render_idea_graph.py
│   └── check_idea_health.py
├── _index.md
├── graph.md
├── viewer.html
└── graph-view.html
```

`ideas/inbox/` 保存尚未结构化的快速记录。正式整理后创建 `ideas/pages/` 页面，并删除对应 inbox 临时文件。原始文字必须原样迁移到正式页的“原始想法”。

Idea 脚本全部位于 `ideas/scripts/`，避免与主知识库脚本混淆。它们可以复用通用依赖，但不得调用会写入主索引或主图谱的脚本。

## 生成物

### `_index.md`

提供面向 Claude 和人工阅读的文本索引，包含：

- 最近记录；
- 最近更新；
- 按状态分组；
- 按问题聚合；
- 按领域聚合；
- 当前阻塞点；
- 组合候选；
- 长期休眠 Idea。

该文件由脚本生成，不手工编辑。

### `idea-index.json`

提供 Web Viewer 使用的结构化目录，包含页面元数据、摘要、状态统计和候选组合摘要。不得包含 Markdown 全文，避免首屏一次性加载所有内容。

### `idea-graph-data.json`

只包含 Idea Lab 内部节点与关系。知识页、论文和项目作为 `external` 节点出现，不参与核心度数和 Idea 总数统计。

## 图谱

节点类型：

- `idea`：正式 Idea；
- `problem`：从 `problem` 字段聚合出的虚拟节点；
- `blocker`：从阻塞点聚合出的虚拟节点；
- `external`：知识页、论文、项目和其他外部引用。

关系类型：

- `addresses`：Idea 试图解决某个问题；
- `blocked_by`：Idea 被某个阻塞点限制；
- `derived_from`：组合 Idea 来源；
- `combined_into`：来源 Idea 指向组合结果；
- `related_to`：一般 Idea 关联；
- `references`：指向外部对象。

默认图谱视图优先展示：

- 被阻塞的 Idea；
- 被多条 Idea 共享的阻塞点；
- 由多条旧 Idea 形成的组合链；
- 从 `dormant` 或 `blocked` 重新激活的 Idea；
- 尚未建立任何关系的孤立 Idea。

## Web UI

正式 UI 以已确认的 `idea-lab-prototype.html` 为视觉基线。

### 桌面布局

采用三栏结构：

1. 左栏：状态视图、组合机会、最近更新和 Idea 列表；
2. 中栏：当前 Idea 正文、元数据、尝试和演化记录；
3. 右栏：组合候选、阻塞点及外部知识引用。

右栏展示的是当前 Idea 的关系上下文，不承担全库导航。窗口不足时优先隐藏右栏，保留左栏导航和正文。

### 快速记录

主操作“记录 Idea”只要求：

- 一句话 Idea，必填；
- 想解决的问题，可选。

保存后进入 inbox，不调用 Claude，不阻塞用户继续操作。用户可以稍后选择“整理为正式 Idea”。

### 记录尝试

从当前 Idea 进入独立表单，收集方案、结果、失败或不足、保留价值和重新启动条件。提交后追加到页面，不覆盖已有尝试。

### 组合确认

候选卡必须先显示匹配理由。用户选择两条或多条 Idea 后进入组合草稿页，由 Claude 或本地模板生成初稿；保存前用户可以修改，保存后再写入双向关系。

### 视觉语言

- 延续现有 Viewer 的白色正文、深灰文字和绿色主操作。
- 琥珀色只表示阻塞、未验证和需要注意的状态。
- 不使用大面积彩色背景或装饰性渐变。
- 状态使用文本和颜色共同表达，不能只依赖颜色。
- 正文保持文档感，关系候选使用紧凑卡片，不在正文中嵌套卡片。

## Claude Skill

项目级 Skill 名称暂定为 `capture-idea`，位于 `.claude/skills/capture-idea/`。它只负责 Idea Lab，不执行主知识库摄入协议。

必须遵守：

1. 创建前读取 `ideas/_index.md` 并搜索相似 Idea。
2. 保留用户原始输入，不进行替换式润色。
3. 明确区分事实、假设、个人判断和待验证内容。
4. 不要求 Idea 提供可靠来源或信度。
5. 记录失败时提取阻塞点、保留部分和重新启动条件。
6. 发现组合机会时提出候选和理由，不自动合并。
7. 组合时创建新 Idea，并保持来源关系双向一致。
8. 不运行或修改主知识库的索引、分类和图谱。
9. 不因为 Idea 与知识页同名而把两者合并。
10. Git 提交只包含本次 Idea 及 Idea Lab 生成物。

## 健康检查

独立健康检查至少覆盖：

- ID 缺失、格式错误或重复；
- 文件名 ID 与 frontmatter ID 不一致；
- 无标题或无“原始想法”；
- 非法状态；
- 日期格式错误；
- `blocked` 状态没有阻塞点；
- `abandoned` 状态没有放弃理由；
- `derived_from`、`combined_into` 或 `related_ideas` 指向不存在的 ID；
- 组合关系不是双向；
- Idea 自己引用自己；
- 索引或图谱数据过期；
- inbox 项已迁移但残留重复正式页。

健康检查不得因为外部知识页不存在而阻断 Idea 保存；外部引用失效只产生警告。

## 首版范围

首版实现以下闭环：

1. 快速保存 Idea 到 inbox；
2. 将 inbox 条目整理为正式 Idea；
3. 浏览、搜索并按状态筛选 Idea；
4. 给 Idea 追加尝试记录；
5. 维护阻塞点和重新启动条件；
6. 基于本地信号生成组合候选及解释；
7. 用户确认后创建组合 Idea；
8. 生成独立索引和独立图谱；
9. 运行独立健康检查；
10. 通过独立 Skill 调用相同工作流。

首版明确不包含：

- 自动执行 Idea；
- 自动改变状态；
- 自动合并 Idea；
- 项目任务管理、排期或看板；
- 基于上游大模型的后台持续分析；
- 将 Idea 自动转化为知识页或工程项目；
- 移动端专门优化。

## 验收标准

- Idea Lab 不修改主知识库的索引、分类和图谱数据。
- 快速记录在不调用 Claude 的情况下完成。
- 原始输入能够从 inbox 无损迁移到正式 Idea。
- 页面使用稳定 ID，改标题不破坏关系。
- 同一 Idea 可以保存多次尝试，旧尝试不会被覆盖。
- `blocked` Idea 能明确展示阻塞点和重新启动条件。
- 新 Idea 可以得到带具体解释的旧 Idea 组合候选。
- 未经确认不会创建组合或修改旧 Idea。
- 组合创建后来源关系双向一致。
- 独立索引、Viewer、图谱和健康检查可从 `ideas/` 内单独运行。
- WebUI 桌面版视觉和交互与确认过的原型一致。
- Idea Lab 的失败不会使主知识库 Viewer、刷新和健康检查失败。
