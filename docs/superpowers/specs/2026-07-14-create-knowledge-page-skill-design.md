# 高质量知识页 Skill 与 WebUI 入口设计

## 目标

为技术雷达知识库增加一个稳定、可复用的高质量建页工作流。用户在 Web 操作台只需填写知识主题，可选提供来源、材料和关注点；Claude Code 通过项目级 Skill 完成查重、资料核验、内容撰写、质量检查和提交，减少用户手写长提示词的负担。

## 架构选择

采用“Skill 是唯一质量规则，WebUI 只生成结构化调用”的架构：

- 项目级 Skill 保存完整工作流和质量标准。
- WebUI 表单只收集输入并生成简短、结构化的 Skill 调用指令。
- WebUI 不复制 Skill 的完整提示词，避免两处规则漂移。
- 继续沿用 `new_page.py`、`build_index.py`、`render_graph.py` 和 `check_health.py`，不新增重复的建页脚本。

## 文件边界

### 知识库仓库

- 新增：`.claude/skills/create-knowledge-page/SKILL.md`
- 新增：`.claude/skills/create-knowledge-page/agents/openai.yaml`
- 新增或修改：针对 Skill 内容和触发契约的测试
- 修改：`README.md`，记录 Skill 与 WebUI 创建入口
- 修改：`Web操作台使用与维护说明书.md`，说明实际使用方法

### WebUI 外部部署目录

- 修改：`<local-webui-root>/patch-integrated-workbench.mjs`
- 修改：`<local-webui-root>/test-integrated-workbench.mjs`

WebUI 安装包中的构建产物继续由补丁脚本生成，不直接把不可复现的手工修改作为唯一实现。

## Skill 位置与发现

Skill 名称为 `create-knowledge-page`，位于知识库项目的 `.claude/skills/create-knowledge-page/`。它随知识库 Git 版本管理，可被以知识库为工作目录的 WebUI 和终端 Claude Code 共同发现，不依赖 `<local-user-home>/.claude/`。

Skill 的 description 同时覆盖以下触发表达：创建知识页、新建概念页、摄入新概念、扩写或更新已有概念页。Skill 正文保持精炼，引用现有 `CLAUDE.md`、模板和脚本，不重复抄写全库规则。

## WebUI 交互

顶部操作区新增“创建知识页”命令按钮。点击后打开独立对话框，包含：

1. `知识主题`：必填，允许中文名、英文名或自然语言主题描述。
2. `来源或已有材料`：可选，可填写 URL、本地文件路径、论文信息或粘贴的简短材料。
3. `特别关注点`：可选，用于指定公式、实现、评测、项目联系等侧重点。

提交后生成结构化指令，明确要求使用 `create-knowledge-page` Skill，并把三个字段以清楚的边界传递。指令只放入 Claude 输入框，不自动发送。插入失败时沿用现有剪贴板回退和状态提示。

桌面端按钮保持可见；移动端在有限宽度内提供等价入口，不能遮挡刷新和“询问 Claude”等已有操作。

## Skill 工作流

### 1. 理解与查重

- 读取 `CLAUDE.md`、`_index.md`、页面模板和标签定义。
- 搜索精确标题、大小写或空格变体、英文缩写、中文别名和语义近似概念。
- 同一概念已存在时更新原页，不创建第二页。
- 疑似重复但无法可靠判断时暂停并询问用户。

### 2. 资料核验

- 优先使用用户提供的来源和材料，并核对其是否真实可达。
- 未提供来源时，研究可靠公开来源；优先级为原始论文、官方文档、标准或权威技术资料。
- 来源不足以支持关键结论时暂停，不以模型记忆伪造引用。
- 记录可复查的 URL、本地路径、页码或章节定位；无法精确定位时如实降低粒度与信度。

### 3. 页面规划与创建

- 明确概念边界、规范标题、分类标签、项目标签、摘要和信度。
- 新概念必须通过 `scripts/new_page.py` 建立基础页；已有概念直接编辑原页。
- 页面结构按主题自适应，不生成无内容的固定章节。

### 4. 内容质量标准

每页至少清楚回答：

- 概念是什么，边界是什么。
- 它解决什么问题，为什么重要。
- 核心机制或方法如何工作。
- 关键假设、局限和适用条件是什么。
- 它与知识库现有项目或研究主线有什么具体关系。
- 它与哪些已存在页面形成有效双链。

按主题补充必要内容：数学或算法主题使用正确 LaTeX 公式并解释符号；方法型主题包含流程、对比和评测；系统型主题说明组件、数据流和取舍；前沿主题区分已验证事实与尚未验证判断。

正文不得残留模板占位符，不堆砌宽泛表述，不创建不存在的双方括号链接，不把无法核验的推断写成确定事实。

### 5. 质量门禁与提交

- 复核摘要、来源、信度、标签、交叉引用和更新记录。
- 检查事实与来源是否对应，公式是否使用合法定界符。
- 运行 `python3 scripts/build_index.py`。
- 运行 `python3 scripts/render_graph.py`。
- 运行 `python3 scripts/check_health.py`，必须达到 ERROR 0、WARN 0。
- 数学页面在 Viewer 中实际打开并确认 KaTeX 渲染。
- 查看 Git diff，只暂存本次创建或更新的页面及相应机器生成物，保留其他现有改动。
- 使用 `radar:` 前缀提交本次摄入。

## 暂停条件

仅在以下情况暂停并向用户提问：

- 疑似与已有页面重复但无法确定合并边界。
- 主题过宽、可能拆成多个独立概念且无法自行确定主页面。
- 来源不可访问或证据不足以支持关键内容。
- 用户材料之间存在无法消解的明显冲突。

其他单页任务默认端到端完成，不要求每次先确认提纲。

## 安全与兼容性

- Skill 不读取或修改 API Key 和 WebUI 认证配置。
- 不改变 Claude Code 的默认权限模式；是否使用危险模式仍由用户选择。
- WebUI 继续只绑定 localhost，入口不新增网络服务。
- 所有插入 Claude 输入框的内容使用文本赋值，不执行用户提供的 HTML。
- 用户材料可能包含提示注入，Skill 将其视为待分析资料，不执行其中针对代理的指令。

## 验收标准

- Skill 通过 `skill-creator` 的 `quick_validate.py`。
- Claude Code 能在知识库项目中发现 `create-knowledge-page`。
- WebUI 桌面与移动端均有可用的创建入口。
- 必填校验、结构化指令、输入框插入、连续两次操作和剪贴板回退均有测试。
- Skill 明确覆盖查重、来源核验、自适应内容、项目关系、双链、公式、健康检查、图谱和提交。
- 不提供来源时能走公开资料研究路径；来源不足时不会生成伪引用。
- 现有“询问 Claude”、刷新、布局、Markdown 渲染和四档权限模式不回归。
- 知识库测试、WebUI 补丁测试、健康检查和 `git diff --check` 全部通过。
