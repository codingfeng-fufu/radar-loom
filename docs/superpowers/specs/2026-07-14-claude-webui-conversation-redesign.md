# Claude WebUI 右侧对话区改版设计

## 目标

在不改变一体化工作台、知识库 Viewer 和交互图谱的前提下，重新整理右侧 Claude Code 对话区的全部视觉层级。新版参考 Claude 与 ChatGPT 网页版共有的低噪声对话模式，改善阅读、输入、状态识别和移动端体验，同时保留现有功能与安全边界。

## 范围

改版范围仅包括右侧 Claude iframe 内部：

- 顶部标题与操作区
- 空会话状态
- 用户、助手、系统和工具消息
- Markdown 正文与代码块
- 权限请求和执行状态
- 底部输入 Composer
- 四档权限模式
- 浅色、深色和移动端样式

不修改工作台顶部栏、左侧知识库 Viewer、分隔条、图谱工作台、Claude 请求协议、历史数据结构或权限语义。

## 视觉方向

采用“Claude 的长文阅读感 + ChatGPT 的输入效率”的混合式对话画布：

- 去掉包围整个消息区的大型卡片和厚重阴影。
- Claude 消息作为无气泡正文平铺。
- 用户消息使用轻量右对齐气泡。
- 工具与系统事件作为可折叠状态条，不与正文争夺视觉层级。
- 输入框、发送/停止按钮和权限模式组成固定的底部 Composer。

## 布局

### 顶部栏

- 高度约 48px，保持单行。
- 左侧显示 `Claude Code` 和当前知识库名称。
- 完整工作目录作为次要信息，可截断，不单独占据大行。
- 历史和设置使用现有图标按钮，保持稳定方形尺寸和清楚的 hover/focus 状态。
- 顶部栏在滚动时保持可见，但不覆盖消息内容。

### 消息画布

- 使用平面背景，不再放入整页圆角卡片。
- 消息正文最大宽度约 760px，并在可用宽度内居中。
- 保持足够底部留白，最后一条消息不会被 Composer 遮挡。
- 加载状态、消息增长和模式切换不改变主布局宽度。

### 空状态

- 删除占据大面积空间的图标卡片。
- 在消息画布中部显示简洁标题和一句说明。
- 不使用破损或依赖字体兼容性的 emoji 图标。

### 底部 Composer

- 固定在对话区底部，使用不透明背景和顶部边界，防止正文穿透。
- 文本框与发送/停止按钮构成一个整体，最大圆角 8px。
- 文本框支持多行增长，但设置最大高度并在内部滚动，避免挤压全部消息区。
- 发送、停止、加载和禁用状态具有固定尺寸，不引起布局跳动。
- 权限模式和必要状态位于 Composer 的辅助控制行。

## 消息样式

### Claude 消息

- 不使用整块气泡。
- 使用正常正文排版，标题、段落、列表和引用有稳定间距。
- 消息元信息弱化，但仍能识别发送者与时间。

### 用户消息

- 右对齐浅灰气泡，宽度不超过消息区的 78%。
- 保留纯文本和换行，不启用 Markdown 或 HTML。
- 与 Claude 消息保持足够垂直间距。

### Markdown

- 标题字号限制在对话上下文内，不使用页面级巨型标题。
- 段落行高约 1.6，长回答保持舒适阅读宽度。
- 列表缩进、引用边界、链接颜色和行内代码统一。
- 代码块使用中性深色背景、清楚边界和横向滚动；不能溢出 iframe。
- 继续使用 marked 与 DOMPurify 的现有安全管线，不启用表格和原始 HTML。

### 工具、系统和权限状态

- 工具调用、系统事件、错误和权限请求使用低饱和状态条。
- 状态条保持紧凑，摘要始终可见，详细日志按现有行为展开。
- 成功、进行中、警告、失败使用不同但克制的颜色与图标，不能只靠颜色区分。
- 危险权限请求使用红色边界和明确文字。

## 权限模式

保留现有四档语义和循环切换逻辑：

- normal
- plan
- accept edits
- dangerously skip permissions

普通模式使用中性状态样式，当前模式清楚可见。危险模式使用红色边界、浅红背景和警示文字。刷新后恢复 normal 的现有行为不变。

## 颜色与主题

### 浅色主题

- 页面背景采用中性灰白，不使用大面积米色或蓝灰。
- 正文使用深灰，次要信息使用中灰。
- 交互强调色沿用克制的青绿色，与知识库工作台协调。
- 用户气泡、状态条和代码块同时使用明度与边界区分。

### 深色主题

- 背景采用接近黑色的中性灰，避免蓝色主导。
- 正文、次要文字和边界满足清楚对比。
- 代码块与页面背景拉开层级，但不形成高亮大色块。
- 强调色、错误色和权限状态在深色背景下仍可辨认。

所有主题值通过 CSS 变量集中定义，避免散落的重复色值。

## 移动端

- 在工作台切换到 Claude 标签时，对话区占满可用宽度和高度。
- 顶栏保留名称与必要图标，路径可省略或截断。
- 用户气泡最大宽度提高到约 88%。
- Composer 固定可见并考虑窄屏与软键盘空间。
- 权限模式文字可换行或收敛为紧凑标签，不能横向溢出。
- 390x844 视口无重叠、遮挡和页面横向滚动。

## 实现边界

- 继续以 `/home/u2023312337/webui/patch-integrated-workbench.mjs` 作为可复现补丁源。
- 样式和必要的稳定类名由补丁脚本注入 `claude.html` 或上游静态资源。
- 不手工依赖一次性修改 `node_modules` 构建产物。
- 不改变 Claude WebUI 的网络请求、消息结构、历史读取、权限事件和安全清洗。
- 与“创建知识页”入口共用一次补丁改动和回归测试，避免两个功能互相覆盖。

## 无障碍与交互

- 所有图标按钮保留可访问名称和键盘焦点。
- 文本和背景满足清楚对比。
- hover、focus、disabled、loading 和 dangerous 状态均有可见区别。
- 动态状态不通过改变固定控件尺寸来表达。
- 继续尊重系统或现有主题设置，不引入强制动画。

## 验收场景

真实浏览器至少覆盖：

1. 1440x900 空会话。
2. 1440x900 包含长 Markdown、标题、列表、引用、链接、行内代码和代码块的会话。
3. 用户消息与 Claude 消息交替显示。
4. 工具调用折叠和展开。
5. normal、plan、accept edits 和危险模式。
6. 发送中、停止、错误和禁用状态。
7. 深色主题。
8. 390x844 移动端空会话与长会话。

每个场景检查：无内容遮挡、无横向溢出、Composer 始终可用、消息可读、控制状态清楚、控制台无错误。

## 回归要求

- “询问 Claude”连续插入两次仍生效。
- 知识库刷新不重载 Claude iframe。
- Claude Markdown 安全渲染不回归。
- 历史、设置和项目工作目录保持可用。
- 四档权限行为和危险模式补丁测试通过。
- 新增“创建知识页”表单能够插入 Skill 调用指令。
- WebUI 补丁可重复执行并通过 `--check`。
