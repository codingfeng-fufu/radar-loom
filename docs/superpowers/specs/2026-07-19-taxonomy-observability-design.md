# 动态分类可观察性设计

## 背景

当前动态分类系统已经能够为页面计算多重归属，但用户难以从界面判断自动分类是否运行、是否形成了新类别，以及全局重组为何没有改变现有结构。普通知识库当前的八个类别均来自历史标签迁移；最近一次全局重组被保护机制拒绝。工程面试区页面数量尚未达到正式成类门槛。这些状态虽然存在于注册表和事件记录中，却没有形成直观的产品反馈。

本设计升级现有图谱页的“分类结构”模式，使分类过程、候选类别和演化结果可见，同时保持界面简洁。它不新增第四种图谱模式，也不改变知识关系图谱与工程面试区隔离的原则。

## 目标

1. 用户能一眼区分初始种子、自动形成的正式类别和正在形成的候选类别。
2. 两个相近页面即可显示候选进度，例如 `2/3`，而不必等待正式成类后才获得反馈。
3. 用户能看到最近一次分类或重组的真实结果，包括成功、未采用和失败。
4. 分类图谱默认简洁，按需展开代表知识页和归属证据。
5. 圆形节点、连线端点、布局稳定性和标签可读性成为明确验收标准。
6. 所有候选计算使用本地向量与图结构，不增加付费模型调用。

## 非目标

- 不新增独立的“分类观察”页面或第四种图谱模式。
- 不在 Viewer 首页复制完整诊断面板。
- 不让前端自行计算聚类、候选类别或运行结论。
- 不混合普通知识库和工程面试区的分类数据。
- 不改变现有知识页人工标签，也不将候选类别写回页面 frontmatter。
- 不在候选阶段调用 Claude 命名。

## 总体体验

Viewer 顶部增加一行紧凑的动态分类摘要。示例：

```text
动态分类  8 个种子 · 1 个候选 · 最近重组未采用    打开分类结构 →
```

点击该摘要后，打开图谱页并直接进入现有“分类结构”模式。分类结构以圆形类别节点为主体：初始种子、自动正式类别和候选类别具有不同但克制的视觉编码。默认只显示类别层；点击类别后，其代表知识页围绕类别节点局部展开。再次点击类别或点击画布空白处收起。

顶部只保留一条紧凑状态，不常驻展示完整指标。运行原因、事件历史、归属分数和证据均在点击相关状态或节点后显示于现有右侧详情区。

## 信息架构

### Viewer 摘要入口

摘要只承担发现和跳转职责，内容包括：

- 初始种子数量；
- 自动正式类别数量；
- 候选类别数量；
- 最近一次需要关注的运行结果。

入口使用显式 URL 参数 `mode=taxonomy`，使图谱首次打开即进入“分类结构”，并让该参数优先于浏览器中遗留的会话状态。

### 分类结构模式

现有“分类结构”模式直接升级，不新增模式按钮。默认画布仅显示活动类别和候选类别。右侧详情区在未选择节点时保持简洁提示；选择节点后按节点类型展示详情。

类别详情包括来源、状态、成员数、定义、父类、相关类别和最近演化事件。候选详情包括临时名称、成员页、当前进度、凝聚度、主要证据、首次发现时间和最近确认时间。知识页详情包括所属类别、分数、各项信号、归属理由和打开页面的入口。

## 图谱视觉与交互

### 节点

所有类别与展开后的代表知识页均使用圆形节点。节点宽高固定相等，不因标签长度改变形状。

- **初始种子**：暖色实线边框，显示“初始种子”来源标识。
- **自动正式类别**：冷色实线边框，显示类别状态和成员数。
- **候选类别**：绿色虚线边框与低对比度外环，直接显示进度，如 `2/3`。
- **代表知识页**：尺寸小于类别节点，使用中性色边框；选中时显示清晰焦点环。
- **合并类别**：不作为默认活动节点显示，通过目标类别详情中的别名和历史事件访问。

节点标签限制为适合圆形区域的短名称。过长名称在画布上按安全长度换行或截断，完整名称始终可在详情区读取。字体不随视口宽度连续缩放。

### 边

每种边只表达一种固定语义：

- 父子关系：带方向的实线；
- 相关类别：低对比度曲线；
- 候选与相近类别：绿色虚线；
- 正式页面归属：蓝灰实线；
- 候选成员归属：绿色实线。

边从圆周锚点出发和结束，不穿过节点的可见内容区域。布局和边路由应减少无关节点穿越、交叉堆叠和平行边重合。边标签默认隐藏，仅在选中节点或边时显示分数或关系名称。

### 局部展开

默认只显示类别层。点击类别后，最多展开一组有限的代表知识页，并围绕所属类别进行局部布局；不一次性显示该类别的全部成员。候选类别展开其当前全部候选成员，因为候选规模受形成门槛约束。

展开不应触发整个图谱的大幅跳动。再次点击该类别或点击空白处收起临时页面节点。刷新页面后恢复分类模式和视口，但不恢复展开节点，以免初始画面杂乱。

## 候选类别模型

### 形成规则

现有正式形成门槛保持为三个页面。新增候选阶段：两个达到相似性和结构证据要求的页面即可组成候选类别，显示为 `2/3`。候选计算复用现有本地嵌入、页面引用和确定性结构信号。

单个未归属页面不显示为候选类别。候选达到正式门槛后进入现有 `forming` 生命周期；不再满足候选条件时从当前候选快照中移除。

### 持久化字段

分类注册表保存候选快照。每个候选至少包含：

- 稳定候选 ID；
- 确定性临时名称；
- 成员页面路径；
- `cohesion_score` 综合凝聚度分数；
- 形成目标和当前进度；
- 主要信号摘要；
- 首次发现时间；
- 最近确认时间。

候选 ID 根据规范化成员路径稳定生成，避免无变化刷新造成身份抖动。候选不是正式类别，不进入正式类别计数、父子层级或 Claude 命名预算。

### 命名与成本

候选临时名称使用确定性关键词命名器生成，不调用 Claude。候选晋升为正式类别后，才按现有预算和降级规则进入类别命名流程。候选计算只使用本机缓存和已有依赖，不增加外部 API 成本。

## 数据流

1. `taxonomy_cli sync` 扫描变化页面并更新页面归属。
2. 引擎使用现有向量缓存和结构信号重算受影响的候选群组。
3. 只有完整通过注册表校验的正式类别、归属和候选快照才原子发布。
4. 全局重组运行后重新核对候选；已经进入正式群组的候选被晋升或移除。
5. `render_graph.py` 将类别来源、候选快照、运行摘要和事件原因写入对应图谱数据。
6. Viewer 与图谱前端只消费生成数据，不推断分类状态。
7. 文件变化触发现有 revision 机制，图谱重新加载数据并保持当前分类模式。

知识库与工程面试区分别使用自己的配置、注册表、缓存和图谱数据。两个 profile 的候选 ID、成员和状态不得互相引用。

## 运行状态

界面明确区分以下结果：

- **正常且无变化**：中性色，不使用抢眼的成功提示；
- **存在候选**：绿色小圆点和候选数量；
- **全局重组成功采用**：显示更新时间和结构变化摘要；
- **全局重组未采用**：琥珀色“结构未更新”，可展开保护机制原因和时间；
- **分类计算失败或数据陈旧**：红色“分类数据未更新”，同时继续展示上一版有效数据。

手动全局重组必须返回“采用”“未采用”“失败”三种不同业务结果，不能把进程正常退出一律描述为成功。运行中按钮保持忙碌状态并防止重复请求。

候选计算失败时保留上一份有效候选快照，并标记其最近成功更新时间。界面不得将“本轮无法计算”显示为“当前没有候选”。

## 错误处理与兼容性

- 注册表 schema 或候选字段校验失败时，不发布部分结果。
- 旧注册表首次读取时将缺失候选字段解释为空列表，并由下一次成功同步写入新格式。
- 图谱数据缺少候选信息时仍能显示正式分类结构，同时把观察状态标记为不可用，而不是导致整个图谱空白。
- 真实分类结果优先于临时界面状态；revision 更新后清除已经过期的局部展开节点。
- 保护机制拒绝候选全局结构时保留上一版正式结构，但必须发布可审计的拒绝结果和原因。

## 测试与验收

### 分类引擎

- 两个相近页面形成稳定候选并显示 `2/3`；
- 第三个相近页面使候选晋升为正式 `forming` 类别；
- 候选条件消失时正确移除候选；
- 重复同步无变化时注册表保持幂等；
- 候选计算失败时保留旧快照并暴露陈旧状态；
- 知识库和工程面试区候选完全隔离；
- 候选命名不调用外部命名命令。

### 数据契约

- 图谱数据包含类别来源、候选进度、运行结果、事件原因和时间；
- 所有候选成员、类别关系和归属边引用现有节点；
- 旧注册表和无候选状态保持兼容；
- `render_graph.py` 重复运行结果稳定。

### 前端行为

- Viewer 摘要能可靠跳转到分类结构模式；
- 三类类别节点视觉可区分，且不仅依赖颜色；
- 类别点击展开有限代表页，再次点击或空白点击收起；
- 页面详情显示归属分数、信号、理由和跳转入口；
- 手动重组正确区分运行中、采用、未采用和失败；
- revision 更新后保持分类模式并移除过期展开节点。

### 视觉验收

使用 Playwright 在桌面和移动视口进行真实浏览器截图检查：

- 类别与页面节点保持正圆；
- 最长标签不溢出圆形区域，不遮挡其他节点；
- 边连接圆周，不穿过无关节点；
- 默认布局、展开布局和重新布局后均无节点重叠；
- 边标签不覆盖节点或彼此堆叠；
- 图谱非空且合理占满可用画布；
- 右侧详情和移动端底部详情不遮挡关键控制；
- 数据更新前后没有明显布局闪烁或错误旧候选。

最终验证还包括完整自动化测试、分类注册表校验、图谱生成和知识库健康检查。

## 成功标准

用户进入 Viewer 后无需查看日志即可知道动态分类是否运行、是否存在候选、最近一次重组是否采用。进入“分类结构”后，可以通过圆形节点和有意义的边立即区分初始种子、自动类别和候选类别，并能按需查看代表页、归属依据和演化原因。界面保持简洁，默认画布不被全部页面和诊断指标淹没。
