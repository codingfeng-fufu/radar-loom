# Web 操作台可用性修复设计

## 背景

技术雷达知识库已经具备 Markdown Viewer、交互图谱、动态分类、知识页创建入口和 Claude Code WebUI。2026-07-16 的端到端体验测试确认核心流程可用，同时发现弹窗阻断、图谱上下文过期、刷新丢失状态、Viewer 缺少搜索、首页导览过时、公共 CDN 依赖和移动端缺字图标等问题。

本设计覆盖该次测试报告中的全部问题。修复继续沿用当前静态 Viewer、单页图谱和补丁式操作台，不引入新的前端框架，也不改变知识页 Markdown 格式、动态分类数据格式或现有服务端口。

## 目标

1. 消除会阻断用户继续工作的弹窗问题。
2. 让 Claude 始终收到与当前 Viewer 或图谱状态一致的上下文。
3. 让知识页在 100 页以上规模下仍能快速查找和浏览。
4. 在图谱刷新和数据热更新后恢复用户的工作位置。
5. 使数学公式、图谱和 Markdown 渲染在断网环境下稳定工作。
6. 更新首页导览，使 Web 操作台成为默认使用入口。
7. 消除移动端缺字图标、加载闪烁和明显布局摩擦。
8. 用真实交互测试覆盖关键行为，避免只检查源码标记。

## 非目标

- 不迁移到 React、Vue 或其他新框架。
- 不修改知识页 frontmatter、标签体系或动态分类算法。
- 不重新设计 Claude Code WebUI 的整体对话视觉。
- 不改变 `18080`、`18081` 服务职责和本机访问模型。
- 不把本轮工作扩大为全文检索服务或独立数据库。

## 总体架构

修复分为三个既有边界：

- `<local-webui-root>/patch-integrated-workbench.mjs` 负责外层操作台、弹窗、Claude 输入桥接、当前上下文和刷新反馈。
- `viewer.html` 负责知识页导航、搜索、目录状态、Markdown 渲染和知识页上下文上报。
- `graph-view.html` 负责图谱交互状态、状态恢复、图谱上下文上报和热更新。

Viewer 与图谱通过 `window.parent.postMessage` 向操作台发送结构化上下文。操作台只接受来源为 `http://127.0.0.1:18081` 且 `event.source` 等于知识库 iframe `contentWindow` 的消息。操作台不读取 iframe URL 猜测上下文。

## 上下文协议

### 知识页上下文

Viewer 成功渲染页面后发送：

```json
{
  "type": "kb-context",
  "context": {
    "kind": "page",
    "file": "pages/扩散模型 Diffusion Models DDPM.md",
    "title": "扩散模型 Diffusion Models DDPM"
  }
}
```

### 图谱上下文

图谱首次载入、切换模式、修改筛选或选择节点后发送：

```json
{
  "type": "kb-context",
  "context": {
    "kind": "graph",
    "mode": "combined",
    "modeLabel": "综合视图",
    "visibleNodes": 84,
    "visibleEdges": 216,
    "categories": ["KG", "RAG"],
    "projects": [],
    "selected": {
      "id": "扩散模型 Diffusion Models DDPM",
      "label": "扩散模型 Diffusion Models DDPM",
      "nodeType": "concept",
      "neighbors": ["变分自编码器 VAE Variational Autoencoder", "前向过程"]
    }
  }
}
```

没有选中节点时 `selected` 为 `null`。操作台验证字段类型并丢弃未知或越界数据。

### Claude 提示词

- `kind: page`：要求 Claude 先读取对应知识库文件，再回答用户问题。
- `kind: graph` 且存在 `selected`：提供节点名称、类型、当前模式和邻接节点，要求围绕选中节点回答。
- `kind: graph` 且无 `selected`：提供当前模式、筛选和可见节点/边数量，要求围绕当前图谱视图回答。

操作台标题和询问弹窗分别显示“当前页面”或“当前图谱”，不再把图谱伪装为最后访问的 Markdown 文件。

## 弹窗行为

询问 Claude 和创建知识页使用同一套关闭规则：

- 取消按钮显式使用 `type="button"`，调用统一的关闭函数。
- `Escape` 使用原生 `cancel` 事件关闭。
- 点击 `dialog` 遮罩区域关闭；点击弹窗内容不关闭。
- 关闭动作可以重复调用，不抛异常。
- 关闭后焦点返回打开弹窗的按钮。
- 只有成功写入 Claude 输入框或成功复制到剪贴板后，插入动作才关闭弹窗。
- 直接写入和剪贴板回退都失败时，弹窗保持打开并展示可读错误。

创建弹窗提交前继续执行浏览器必填校验。取消不会提交表单，也不会清空用户已填写内容；成功插入后才清空字段。

## Claude 草稿

操作台在刷新知识库前读取 Claude textarea 的当前内容，并保存到 `sessionStorage`。Claude iframe 重新载入且输入框就绪后恢复草稿，并触发原生 `input` 事件，使 React 状态与 DOM 一致。

草稿按当前 Claude 项目会话隔离，只保存未发送文本，不保存对话消息。用户发送或主动清空后，同步清除保存项。

## Viewer 搜索与目录

### 搜索索引

Viewer 继续使用 `_index.md`，不新增服务端搜索。索引解析结果扩充为以下字段：

- 页面标题
- 文件路径
- 摘要
- 分类标签
- 项目标签
- aliases

搜索进行 Unicode 小写归一化，按空白拆分查询词，并要求每个查询词至少命中一个字段。结果按标题前缀、标题包含、别名、标签、摘要的优先级排序。

### 搜索交互

- 搜索框固定在目录顶部。
- 输入即时过滤，结果显示标题、摘要片段和分类标签。
- `/` 和 `Ctrl+K` 聚焦搜索框。
- `Escape` 先清空搜索，再关闭移动端目录。
- 空查询恢复分类目录。
- 空结果显示“未找到匹配页面”，正文保持不变。
- 当前页面即使不匹配筛选也以“当前页面”分组保留入口。

### 目录状态

- 首次打开只展开当前页面所属分类；首页不自动展开长分类。
- 用户展开或折叠分类后，将状态保存在 `sessionStorage`。
- 提供“全部折叠”图标按钮及可访问名称。
- 页面切换不清空整个目录 DOM，只更新活动链接和必要分组。
- 初次索引加载使用稳定骨架；后续页面切换不再显示“正在读取索引”。

索引请求失败时显示错误和“重试”按钮，当前正文仍可阅读。

## 图谱状态保存与恢复

图谱使用带版本号的 `sessionStorage` 数据：

```json
{
  "version": 1,
  "mode": "combined",
  "categories": ["KG", "RAG"],
  "projects": ["EvidenceFirst"],
  "neighborOnly": false,
  "showAllLabels": true,
  "selectedNodeId": "扩散模型 Diffusion Models DDPM",
  "zoom": 0.83,
  "pan": {"x": 132.4, "y": 88.1}
}
```

状态在下列事件后保存：模式切换、筛选变化、节点选择或清除、标签切换、布局停止、缩放和平移结束。

恢复顺序：

1. 解析并校验持久化数据；损坏或未知版本数据直接忽略。
2. 加载新 `graph-data.json`。
3. 恢复仍然存在的模式和筛选值。
4. 创建 Cytoscape 元素并应用筛选。
5. 恢复仍存在的选中节点。
6. 恢复 zoom 和 pan。

节点或标签已不存在时只丢弃失效字段，其余状态继续恢复。自动 revision 更新和操作台手动刷新都使用 `loadGraph` 原地替换数据，不再执行 `location.reload()`。刷新失败时保留旧图和旧状态，并显示错误。

## 刷新反馈

操作台刷新按钮显示 `aria-busy` 并依次呈现：

1. 正在更新分类
2. 正在生成索引与图谱
3. 正在恢复视图
4. 知识库已刷新

服务端现有 `/api/refresh` 仍是单请求接口，因此前两阶段是基于请求生命周期的用户反馈，不声称服务端提供尚不存在的精确进度百分比。响应失败或超时后恢复按钮状态，并保留 Viewer、图谱和 Claude 草稿。

## 本地前端资源

固定版本依赖复制到知识库 `vendor/`：

- Marked 15.0.7
- DOMPurify 3.2.4
- Highlight.js 11.11.1 及 GitHub 主题
- Mermaid 11.4.1
- KaTeX 0.16.22、auto-render 和字体
- Cytoscape 3.31.2
- layout-base 2.0.1
- cose-base 2.2.0
- cytoscape-fcose 2.2.0

Viewer 和图谱只引用相对本地路径。Claude WebUI 的 Marked 和 DOMPurify 由 WebUI 自身 `/assets/vendor/` 提供，不跨端口引用知识库资源。

资源文件提交到仓库或 WebUI 部署目录后无需 npm 构建即可运行。缺少核心资源时页面显示具体错误：Viewer 保留原 Markdown 文本，图谱显示资源加载失败面板，不能只产生空白区域。

## 图标与移动端

操作台和图谱工具按钮使用内联、可继承颜色的 SVG 图标，或已有本地 Lucide 资源。每个纯图标按钮保留 `aria-label` 和 `title`。不再使用 `🔧`、`⌗` 等依赖字体覆盖的字符。

390 x 844 验收视口下：

- 顶部全局操作和三标签不重叠。
- 两个弹窗完整位于视口内，内容较高时弹窗内部滚动。
- Claude composer 始终可见，权限模式文本可换行但不覆盖输入框。
- 图谱三个模式按钮、搜索和工具按钮不重叠。
- 筛选与详情继续采用抽屉。

## 首页导览

`首页.md` 首屏改为 Web-first：

- 从操作台浏览、搜索和打开交互图谱。
- 使用“询问 Claude”和“创建知识页”。
- 解释刷新按钮会更新分类、索引和图谱。

命令行脚本和 VS Code 操作保留在“维护与排障”次级章节，不再作为默认浏览路径。项目入口和使用习惯继续保留，但删除已过时的唯一入口表述。

## 测试策略

所有行为变更遵循 Red-Green-Refactor：先编写会因当前缺陷失败的测试，确认正确失败，再做最小实现。

### 契约测试

- Viewer：搜索结构、键盘操作、本地资源路径、目录状态和重试入口。
- 图谱：持久化 schema、恢复顺序、原地刷新、上下文消息和本地图谱依赖。
- 操作台：明确按钮类型、统一关闭函数、上下文验证、图谱提示词、草稿恢复和本地 Markdown 依赖。
- 首页：Web 操作台入口和维护章节存在，旧的首选 VS Code 指引不存在。

### 浏览器交互测试

Playwright 覆盖：

1. 创建弹窗通过取消、`Escape` 和遮罩点击关闭，焦点返回。
2. 插入失败保持弹窗打开并显示错误。
3. Viewer 搜索标题、标签和摘要，键盘快捷键有效。
4. 图谱选择节点后，操作台生成节点上下文提示词。
5. 图谱切换模式、筛选、选择和缩放后刷新，状态恢复。
6. Claude 未发送草稿在知识库刷新后保留。
7. 浏览器阻断外网请求时，公式、代码高亮和图谱仍渲染。
8. 1440 x 900 与 390 x 844 均无横向溢出、遮挡和缺字图标。
9. 浏览器控制台无 error。

### 全量验证

- WebUI Node 补丁测试。
- `python3 -m unittest discover -s tests -v`。
- `python3 scripts/build_index.py`。
- `python3 scripts/render_graph.py`。
- `python3 scripts/check_health.py`，要求 `ERROR 0 / WARN 0`。
- 重新运行补丁脚本并重启两个服务后执行 Playwright 桌面、移动和离线回归。

## 验收标准

只有同时满足以下条件才视为完成：

- 测试报告中的每个问题都有对应实现和自动化证据。
- 创建弹窗不再阻断操作。
- Claude 上下文与当前知识页或图谱一致。
- Viewer 搜索和目录状态在桌面、移动端可用。
- 图谱刷新后恢复有效状态。
- 断网时数学公式、Markdown 和图谱核心功能可用。
- 首页不再把 VS Code 和命令行描述为默认入口。
- 移动端无缺字图标或关键布局溢出。
- 全量测试、健康检查和浏览器控制台检查通过。
