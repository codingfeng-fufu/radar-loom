# Web 操作台桌面体验收口设计

## 背景

技术雷达知识库已具备 Viewer、交互图谱、动态分类、知识页创建、工程面试页创建和 Claude Code WebUI。当前主要能力已完整，剩余问题集中在跨模块状态不一致、操作闭环不明确、历史会话和现场恢复不够稳定，以及视觉和错误表达尚未完全统一。

本轮不增加业务功能，以真实用户旅程组织体验收口。

## 目标与边界

### 目标

1. 让用户始终知道当前位置、系统状态和下一步操作。
2. 让每个长操作具备可信的开始、处理中、成功和失败反馈。
3. 使 Viewer、图谱、外层操作台和 Claude WebUI 具有一致的视觉层级和状态语言。
4. 使刷新、页面切换、历史会话加载和服务重启后的工作现场可预期地恢复。
5. 将关键旅程固化为可重复的真实浏览器验收。

### 范围

- 主要验收桌面双栏操作台，基准视口为 `1440×900` 和 `1112×1243`。
- 移动端只做回归保护，不进行专项视觉打磨。
- 沿用现有静态 Viewer、单页图谱、补丁式 WebUI 和本机双服务架构。
- 不修改 Markdown 数据格式、分类算法、Claude 会话协议或知识页 Skill 的业务职责。
- 不增加页面、按钮、模式或新的后端服务。
- 不进行前端框架迁移。

## 组织方式

实施不按代码模块分割，而是按下列完整用户旅程展开：

```text
进入工作台
  -> 定位知识
  -> 阅读页面或图谱
  -> 询问 Claude
  -> 创建或修改内容
  -> 刷新知识库
  -> 确认结果
  -> 下次恢复现场
```

每个阶段统一检查：当前位置是否明确、操作是否立即得到反馈、处理状态是否可判断、成功后是否能定位结果、失败后是否知道恢复路径。

## 旅程收口

### 1. 进入与恢复现场

检查冷启动、浏览器刷新、服务重启和打开历史会话四种入口。可恢复状态包括当前知识页、双栏比例、图谱模式与筛选、Claude 未发送草稿和当前会话。无法恢复的字段应被局部忽略并明确说明，不能因一个失效字段丢失全部现场。

### 2. 定位与阅读知识

收口 Viewer 目录、搜索、当前页标识和页面切换反馈。使公式、宽表格、代码块、长路径和长文章在两个基准视口内保持稳定阅读节奏。页面切换期间不重建目录或清空已显示正文；加载失败时保留上一个可用内容。

### 3. 图谱浏览

统一图谱初始加载、布局计算、revision 自动刷新、手动刷新和分类重组的状态表达。用户必须能判断当前图谱是否为最新、当前模式和筛选是否生效、重组是否完成。失败时保留旧图和操作状态。

### 4. Claude 协作

收口新会话、历史会话、工具调用、Reasoning、Markdown、错误、限流、权限模式和 Composer。保证历史会话可靠打开，连续两次“询问 Claude”都真实写入 React 输入状态，长会话滚动和 Composer 位置稳定，错误块不会破坏输入区布局。

### 5. 创建或修改内容

继续使用现有知识页和工程面试页 Skill。统一弹窗草稿、插入 Claude 输入框、提交过程和最终结果的反馈。任务完成后应能明确确认页面路径、健康检查、动态分类和刷新结果，但不新增独立任务系统。

### 6. 刷新与结果闭环

刷新过程只显示能被真实系统状态支持的少量阶段，不伪造精确进度。成功后明确说明索引、图谱和分类的更新结果；失败时保留旧视图、Claude 草稿和当前会话，并指明仍可继续使用的部分。

## 优先级

1. **P0：状态丢失或误判。** 包括假写入、刷新丢草稿、历史会话无法打开、旧图被当作新图、失败却显示成功。
2. **P1：操作缺少闭环。** 包括处理中不可见、成功后无法定位结果、错误信息无法指导恢复。
3. **P2：跨模块不一致。** 包括状态色、字号、间距、按钮状态、错误表达和加载表达不统一。
4. **P3：精致度。** 包括细微留白、滚动条、对比度和视觉密度。

同一旅程内先处理高优先级问题，不为了视觉统一掩盖状态错误。

## 统一体验规则

- **位置：** 页面标题、图谱模式、Claude 项目与会话必须有稳定的当前态标识。
- **反馈：** 用同一套语义区分空闲、处理中、成功、警告和失败。
- **进度：** 只显示可被客观观测的阶段，不显示无数据支持的百分比。
- **成功：** 提示中同时表达完成了什么以及结果位于何处。
- **失败：** 使用用户可理解的语句说明影响范围、已保留状态和可执行的恢复动作；技术详情作为次级信息。
- **视觉：** 统一字号层级、中性表面、状态色、6–8px 圆角和桌面密度；避免大面积高饱和状态色。
- **恢复：** 持久化数据必须带版本且局部容错；损坏字段不得阻断其他有效状态恢复。

## 验证策略

### 三层验证

1. **契约测试：** 验证状态 schema、消息协议、恢复函数和稳定语义类。
2. **Playwright 真实操作：** 通过可见控件完成点击、输入、刷新、切换、失败注入和恢复，不直接调用内部实现函数代替用户路径。
3. **视觉检查：** 在两个桌面基准视口生成快照，检查重叠、裁切、留白、滚动、对比度和信息层级。

### 端到端场景

1. 冷启动后恢复上次知识页和双栏比例。
2. 搜索并打开包含公式、表格和代码块的页面。
3. 切换图谱模式、筛选和节点，刷新后恢复现场。
4. 将当前页面问题连续两次放入 Claude，两次均真实写入。
5. 打开长历史会话，验证工具块、Reasoning、Markdown、滚动与 Composer。
6. 模拟 Claude `401`、`429`、流中断和本机服务不可用，检查错误表达和现场保留。
7. 创建知识页后刷新，定位新页并确认索引、图谱、分类和健康状态。
8. 重启 `18080` 和 `18081` 服务后，确认可恢复现场及无法恢复字段的说明。
9. 阻断公网资源，确认 Viewer、公式和图谱仍可用。
10. 连续完成全旅程，浏览器控制台无未处理异常。

## 实施阶段

1. **体验基线盘点：** 逐步执行全旅程，记录问题、复现条件、证据和优先级。
2. **关键旅程收口：** 先处理 P0/P1 的状态、恢复和闭环问题。
3. **视觉与文案统一：** 在已稳定的行为上统一状态视觉、错误表达和阅读层级。
4. **回归与基线固化：** 执行完整旅程、移动端保护性回归、健康检查和文档更新。

## 交付物与完成标准

交付物包括桌面体验基线清单、按优先级拆分的实施记录、自动化旅程测试、视觉快照、统一状态与错误规则、更新后的使用与维护说明书，以及问题关闭记录。

本轮完成不以“存在测试”或“界面变得更统一”作为唯一标准。必须同时满足：

- 关键路径不再需要用户猜测当前状态。
- 常见失败不会破坏当前工作现场。
- 可恢复状态稳定恢复，不可恢复状态有明确说明。
- 关键操作均有可信的开始、处理中、成功或失败闭环。
- 两个桌面基准视口无明显重叠、裁切、不可读对比度或错位。
- 整条真实用户旅程可连续完成，且浏览器控制台无未处理异常。
