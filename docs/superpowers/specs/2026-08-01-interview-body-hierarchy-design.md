# 工程面试页正文层级设计

日期：2026-08-01

## 目标

工程面试页首先服务快速复习，同时保留完整的原理、追问、评分和来源。读者应能在首屏抓住答案骨架，再按需要进入详细内容。

本次调整只涉及正文内容与正文渲染。左侧目录、筛选器、分类图谱和移动端布局不在范围内。

## 现状

当前页面已经包含面试问题、考察意图、30 秒回答、2 分钟回答、原理拆解、追问、常见错误、评分和来源，但这些部分主要沿用普通 Markdown 文档样式。

现有问题包括：

- 30 秒回答和详细解释的视觉权重接近，首屏缺少答案骨架。
- 长段落缺少段首主题，读者难以快速定位机制、取舍和边界。
- 加粗和列表依赖作者临场判断，各页面密度不一致。
- 技术流程只能从文字中还原，现有页面没有稳定的图示规则。
- 模板与建页 Skill 只规定章节是否存在，没有规定章节内部如何组织。

## 选定方向

采用“混合文档”结构。首屏用一个重点摘要块和一张技术图建立认知骨架，后续仍使用连续文档、表格、列表和代码块。正文不采用全卡片布局。

该方向有两点约束：

1. 页面必须适合 10 秒扫描，读者能找到结论、机制和边界。
2. 视觉强化不能破坏 Markdown 的可读性，也不能让长文变成卡片集合。

## 正文结构

### 面试问题

保留原题，控制在一至两句话。材料中包含背景条件时，只保留影响答题范围的条件。

### 考察意图

使用三至五条列表。每条说明一种能力或判断，例如系统分层、端到端链路、工程取舍和验证意识。列表项以短关键词开头，后接具体说明。

### 30 秒回答

Viewer 将这一节渲染为单个重点摘要块。内容固定包含：

1. 一句直接结论。
2. 核心机制或主链路。
3. 关键取舍、边界或失败条件。

该部分不展开论证，不重复 2 分钟回答的全部细节。

### 核心技术图

技术图紧随 30 秒回答。每页原则上使用一至两张图，只有在图能减少理解成本时才加入。

图源按以下顺序选择：

1. 论文或官方文档中的原图。图片必须保存到仓库本地，Markdown 使用相对路径，并记录来源与图注。
2. Mermaid 图。适用于架构、数据流、时序、阶段流程和概念关系。
3. 不放图。表格或短列表能更准确表达时，不为满足数量要求添加图片。

外链图片、授权或来源不明确的图片、纯装饰图不得加入页面。

### 2 分钟回答

保留连续叙述。每段处理一个主题，段首使用一条短主题句概括本段。典型顺序为系统拆分、读写链路、工程机制、取舍与边界。

正文不使用整段加粗。连续三项以上的并列机制改成列表；因果解释和论证保留段落。

### 原理拆解

根据内容选择表达方式：

| 内容关系 | 表达方式 |
| --- | --- |
| 有明确先后顺序 | 编号列表或 Mermaid 流程图 |
| 多个同级机制 | 无序列表 |
| 两个以上维度的比较 | 表格 |
| 因果关系或边界论证 | 连续段落 |
| API、字段或命令 | 代码块或行内代码 |

### 递进追问

每个问题使用三级标题。答案首句直接给结论，随后解释依据、边界和工程例子。问题顺序从概念辨析进入系统取舍，再进入失效模式和验证方法。

### 常见错误与评分标准

常见错误使用短列表，每项说明错误说法及其具体缺陷。Viewer 可以为这一节提供警示语义，但同一页面最多出现两个高权重警示块。

评分标准保留不合格、合格、优秀和加分项的分层。各层要求必须可观察，不能使用“理解深入”“回答优秀”等不可验证描述。

### 来源与更新记录

来源核验和更新记录继续放在页面末尾，降低视觉权重。官方图片的出处写入来源核验，并在图片附近提供简短图注。

## 强调规则

加粗用于答案骨架中的结论词、关键阶段、工程取舍、必须记住的数字、适用边界和段首主题。普通名词、英文缩写和整句话不加粗。

单个段落原则上不超过三处加粗。若多个句子都需要加粗，应先判断该段是否应改成列表、表格或重点块。

列表项采用“关键词：解释”的语义结构，但 Markdown 是否对关键词加粗由内容密度决定。模板和 Skill 不要求每个列表项都加粗。

## Viewer 行为

Viewer 根据工程面试页已有的 `page_type: interview` 元数据启用正文样式，不对普通知识页和项目页生效。

专属样式包括：

- 30 秒回答重点块。
- 边界或常见错误的警示块。
- 官方图片的最大尺寸、留白和图注样式。
- 工程面试页的段落、列表、表格和三级标题间距。

Viewer 不从自然语言中猜测重点，不自动重写 Markdown，也不自动下载图片。内容结构由模板、Skill 和页面正文负责。

Mermaid 继续使用现有本地运行时和严格安全模式。单个 Mermaid 图渲染失败时，页面其他内容仍应可读，并保留能够定位错误图的反馈。官方图片加载失败时显示替代文本，不影响正文布局。

## 模板与 Skill

`templates/工程面试页模板.md` 保留现有必需章节，并在占位内容中写明：

- 考察意图的条目数量和表达方式。
- 30 秒回答的三项固定内容。
- 技术图的选择条件和图注要求。
- 2 分钟回答的段落主题规则。
- 原理拆解如何选择列表、表格或 Mermaid。
- 追问答案必须先给结论。

`.claude/skills/create-engineering-interview-page/SKILL.md` 增加正文质量门槛。Claude 在写页前需要判断：哪些内容值得加粗，哪些并列内容需要分条，是否存在可核验且可本地保存的官方图，以及 Mermaid 是否比表格或文字更合适。

Skill 不得为满足视觉要求生成装饰图，不得引用远程图片，也不得把无法核验的社区图标为官方图。

## 现有页面迁移

本次整理以下三篇现有工程面试页：

- `pages/设计一个AI Agent的记忆系统.md`
- `pages/多头注意力机制的核心作用是什么.md`
- `pages/知识图谱的存储方式与索引优化.md`

迁移只改变段落组织、强调方式和图示，不改变事实、数值、结论、来源、标签、角色、难度或关联概念。每页至少完成以下检查：

1. 30 秒回答符合三项结构。
2. 长段落具有可扫描的主题句。
3. 三项以上的并列内容已判断是否应分条。
4. 技术图有信息增量、来源明确并带图注。
5. 页面末尾的事实与来源仍一一对应。

## 资源目录

官方图片存入工程面试页专用资源目录。文件名使用稳定的 ASCII 标识，并与页面建立清晰对应。资源目录只保存页面实际引用的文件，不保存整篇论文、临时截图或下载缓存。

Mermaid 源码保留在 Markdown 页面内，便于审阅和修改。

## 测试与验收

自动化测试覆盖：

- 模板仍包含全部必需章节，并包含新的正文组织约束。
- Skill 明确官方图、Mermaid、加粗、列表、图注和失败回退规则。
- Viewer 的工程面试专属样式只在 `page_type: interview` 页面启用。
- 本地图片路径能够由知识库服务读取，缺失图片不会阻断正文。
- Mermaid 正常图可以渲染，错误图不会阻断整页。
- 三篇迁移页面通过现有健康检查，索引和隔离图谱不发生意外变化。

桌面端视觉验收使用 1440×900 视口。每篇页面需要满足：首屏可见标题、面试问题和 30 秒回答的主要内容；重点块不挤压正文；图片和 Mermaid 不横向溢出；表格、代码和公式保持可读；长页滚动过程中各级标题可以区分。

## 不在本次范围

- 左侧岗位目录去重或重组。
- 搜索与筛选器调整。
- 分类图谱和工程面试隔离图谱调整。
- 移动端专项重做。
- 自动生成或编辑官方图片。
- 修改现有页面的事实口径与分类。
