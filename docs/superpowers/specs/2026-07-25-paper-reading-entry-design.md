# 论文精读入口设计

## 目标

在桌面 Web 操作台增加“读论文”入口，让用户无需手写提示词即可把论文文件或网页 URL 交给项目级 `$paper-reading` Skill。

## 交互

入口位于“创建知识页”和“询问 Claude”之间。独立对话框包含：

- 论文文件：支持 PDF、Markdown 和 TXT，可多选；
- 论文 URL：每行一个；
- 阅读重点：可选。

文件和 URL 至少提供一种。一次提交的多个材料视为同一篇论文的正文、附录或补充材料；批量阅读多篇论文需逐次提交。

## 数据流

本地文件复用知识库上传服务，使用显式 `destination=papers` 写入 `papers/`。服务端继续执行本机来源、文件数量、总大小、扩展名、MIME、文件名和路径校验。论文 URL 不由 WebUI 抓取，只作为提示词中的来源交给 Claude。

上传完成后，WebUI 生成明确调用 `$paper-reading` 的提示词，列出本地相对路径、URL 和阅读重点，并声明默认输出 `paper-notes/`、不自动创建知识页。提示词直接写入 Claude 输入框后才清空表单；剪贴板降级或失败时保留表单。

## 历史与隐私

成功交接后记录 `paper-reading-handoff` 操作，界面显示“论文精读任务已交接”。历史只保存操作类型、状态和时间，不保存文件内容、URL 或阅读重点。

## 错误处理

- 没有文件和 URL：使用原生表单校验阻止提交；
- URL 非 HTTP(S) 或单行过长：在上传前拒绝；
- 文件上传失败：显示服务端错误并保留表单；
- Claude 输入框不可用：沿用剪贴板降级，保留表单；
- 重复提交同一批文件：复用当前会话上传缓存。

## 验证

- Python：`papers` 目标目录、允许类型、路径和错误分支；
- Node：URL 规范化、提示词、表单清空条件、操作类型；
- Playwright：打开对话框、文件/URL输入、上传、提示词写入、表单保留与历史记录。
