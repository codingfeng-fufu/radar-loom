# 代表项目面试总览

## 推荐展示顺序

1. **FinCoder**：最能展示 Agent 工程、可靠性、安全和评估能力。
2. **同心杯金融知识平台**：展示文档理解、知识图谱、RAG 和确定性数值计算。
3. **Agent Learning Assistant**：展示完整 Agent 产品和全栈落地能力。
4. **OpenFusionKGQA**：展示知识图谱融合、GraphRAG 和科研原型能力。
5. **技术雷达知识库**：展示长期工程化、工具链和自我迭代能力。
6. **NarraGraph（忆绘）**：展示多模态产品、内容生成和交付能力。

## 面试时间分配

- **30 秒**：只讲目标、核心方案和一个结果。
- **3 分钟**：背景 30 秒，架构 40 秒，个人贡献 50 秒，难题 40 秒，结果 20 秒。
- **10 分钟**：在 3 分钟版本基础上展开一个核心技术和一个失败案例。

## 1. FinCoder

### 3 分钟讲解

FinCoder 面向中文财务报表做可审计数值问答。问题在于财务数据有单位、期间、合并/母公司口径和 PDF/Excel 多种格式，普通 LLM 可能算错，也无法证明来源。

架构上，Agent Loop 负责规划和工具调用；工具通过 Schema 和 Pydantic 校验后在 subprocess、worker process 或受控进程内执行；每次计算写入 append-only JSONL 审计链，`ref_node` 组成计算 DAG，节点可以回溯到文件、页码、sheet、行列。审计器再做单位检查、勾稽、同口径 cross-check 和独立重算。

最关键的机制是 Repair 子循环。审计失败后，系统把结构化报告反馈给模型，最多重算两次，预算耗尽后拒绝交付。评估不用 LLM Judge，而是用 Decimal、单位换算、来源匹配和轨迹不变式做七维确定性评分。

结果上，10 份真实 A 股年报的 30 个主报表槽位全部找到，27 PASS、3 WARN、0 FAIL；26 个端到端用例全部通过，测试、ruff 和 mypy 也通过。这个项目最能体现我对 Agent 可靠性、安全边界和评估体系的理解。

### 简历短版

**FinCoder｜带审计回路的财务数值 Coding Agent**

- 设计 Agent Loop、工具隔离执行、append-only 审计链和 `ref_node` 计算 DAG；
- 实现单位检查、来源追溯、交叉核验、独立重算和 Repair 子循环，失败时拒绝交付；
- 构建七维确定性评估框架，10 份真实年报 30/30 报表发现，26 个端到端用例 100% 通过。

## 2. 同心杯金融知识平台

### 3 分钟讲解

同心杯平台面向统计年报、行业台账和经营报表。它没有把所有问题都交给大模型，而是先把 PDF 解析成带来源的文本和表格 Chunk，再抽取实体、关系和结构化事实。

系统有两个物理隔离的向量库：辅助 RAG 库保存原文，服务概念和背景问答；核心事实库保存带时间、数值、单位和维度的事实，服务统计和预测。在线查询由模块五严格二选一：常规问题走原文和可选 Neo4j 固定查询；数值问题走事实库，选择预注册模板后由程序用 Decimal 计算；预测只使用目标时间之前的历史事实拟合线性回归。

最难的是边界控制。原文证据和计算事实不能混用，dataset_version 必须保持向量库和图谱一致，时间冲突和未来数据泄漏必须关闭。每个结果都能通过 fact_id、source_chunk_id 回到 PDF 页码。

这个项目适合展示我如何把大模型限制在识别、选择和语义适配，把精确计算、校验和追溯交给程序。

### 简历短版

**同心杯金融知识平台｜文档问答、数值统计与时序预测**

- 设计 PDF → Chunk → Fact → 双向量库/Neo4j → 问答或计算的七模块架构；
- 采用 FAISS + BM25 + Reranker、严格二选一路由、固定统计模板和 Decimal 确定性计算；
- 建立 `document_id/chunk_id/fact_id/dataset_version` 追溯链，支持来源回溯和版本一致性校验。

## 3. Agent Learning Assistant

### 3 分钟讲解

Agent Learning Assistant 是一个帮助用户学习 Agent、RAG 和工具调用的本地 Web 工作台。它把 Chat、知识问答、代码工具、学习计划、进度、概念图谱和长期记忆放到同一个 Agent 流程中。

核心技术包括 FAISS + BM25 混合检索、RRF 融合、邻居 Chunk 扩展、工具参数归一化和 Self-RAG 最终校验。LLM 输出工具参数后先经过 normalize、validator 和 fallback；回答生成后再检查是否被检索上下文支持，不支持就进入 repair。长期记忆通过重要性门控，避免把所有对话写入上下文。

项目的难点是多模块状态一致和失败定位，因此保留 retrieval state、route trace、集成检查和浏览器 smoke。当前知识库 2051 个文档块，检索 smoke 30/30；需要检索样例的 faithfulness 和 context recall 均为 1.0。

### 简历短版

**Agent Learning Assistant｜本地优先 AI Agent 学习助手**

- 集成 Agent、FAISS/BM25 混合 RAG、代码工具、学习计划、概念图谱和长期记忆；
- 实现工具参数归一化、失败兜底、邻居 Chunk 扩展和 Self-RAG 依据校验；
- 知识库 2051 个文档块，Retrieval smoke 30/30，需要检索样例 context recall 1.0。

## 4. OpenFusionKGQA

### 3 分钟讲解

OpenFusionKGQA 是开放语料知识图谱融合和图约束问答 beta 原型。文档先变成带 provenance 的 text units，再经过实体、关系和三元组抽取；候选结果不会直接写入图谱，而是经过归一、关系对齐、证据检查和评分，无法通过的写入 rejected_triples。

问答侧支持 local/global 路由，并对 text units、entities、community reports 做三层向量召回。JSON artifacts 适合离线 demo 和 CI，Neo4j 是可选 production-path。每次运行保留图谱、证据、citation 和 run events。

结果上，离线 release gate 通过，459 个测试通过；Offline QA 7/7，HotpotQA real100 为 78/100，support recall 1.0。这个结果说明证据召回相对稳定，但最终答案选择仍是主要改进方向。

### 简历短版

**OpenFusionKGQA｜开放语料知识图谱融合与 GraphRAG 问答**

- 实现实体/关系/三元组候选到最终图谱和 rejected-triple 的融合流水线；
- 支持 JSON/Neo4j 图存储、local/global QA、三层向量召回和 citation grounding；
- Offline QA 7/7，HotpotQA real100 support recall 1.0，完整测试 459 通过。

## 5. 技术雷达知识库

### 3 分钟讲解

技术雷达是本地优先的个人知识工程系统。原始 PDF、URL、对话和实验材料进入 raw 区，再由 Agent 结构化成带 frontmatter 和双链的 Markdown 页面。索引、动态分类和知识图谱都是可重建的派生物，Git 记录变更，健康检查验证来源、断链、索引和图谱一致性。

工程重点是把 Agent 修改纳入安全工作流。safe apply 只做白名单文件写入，不接受任意 shell；Web 操作台和 iframe 用版本化 postMessage 传递刷新回执；分类失败保留旧快照，图谱刷新销毁旧实例。

当前 134 个概念页、5 个项目页、8 个工程面试页，图谱 148 节点、855 条边、断链 0。它适合在面试中展示长期维护、工具协议和质量工程能力。

### 简历短版

**技术雷达｜本地优先个人知识工程系统**

- 以 Markdown + Git 构建可审计知识库，开发索引、动态分类、图谱生成和健康检查；
- 集成 Claude Code 与本地 Web 操作台，支持安全建页、检索、刷新和图谱浏览；
- 维护 134 个概念页、148 个图谱节点、855 条边，断链 0。

## 6. NarraGraph（忆绘）

### 3 分钟讲解

忆绘把口述人生故事生成成水彩小册。系统先从文本抽取五幕章节、人物、场景、道具、因果连接和视觉 motif，再为不同年龄阶段生成角色设定图，正文插画引用对应阶段设定图，最后用 PIL 排版标题、旁白、页码和封面并导出 PDF。

它的核心难点是跨章节一致性和可恢复生成。`identity_anchor`、character_stage 和角色设定图约束人物身份，motif 追踪让老槐树、砖墙等元素前后呼应；分析、角色图、插画、排版、PDF 和 QC 分阶段持久化，manifest 记录 prompt 和参考图，失败时可以局部重跑。

目前可交付 PNG、封面、PDF、manifest 和 QC 报告，并提供 CLI、Mock Web 模式和 review contact sheet。它的量化口径主要是产物完整性和工程测试，不应虚构图像质量分数；JSON 知识存储和人工视觉复核仍是边界。

### 简历短版

**NarraGraph（忆绘）｜口述人生故事水彩小册生成系统**

- 搭建“故事文本 → 五幕脚本/视觉知识库 → 角色设定图 → 插画 → PDF”多模态 pipeline；
- 通过 identity anchor、角色阶段参考图和 motif 追踪保持跨章节叙事与人物一致性；
- 提供阶段化 CLI、manifest、QC 报告、contact sheet 和可恢复 Web 工作流。

## 通用收尾句

这几个项目虽然场景不同，但主线一致：我会先把问题拆成可验证的数据和状态，再明确哪些工作交给模型、哪些工作由程序保证，最后用测试、追溯和失败边界把系统做成可演示、可解释、可维护的工程。

## 商业价值主线

每个项目面试时都要补充四句话：

1. **谁在使用**：明确到岗位或组织，而不是泛泛说“用户”。
2. **谁来买单**：区分最终使用者、预算决策者和受益部门。
3. **替代什么成本**：人工检索、重复录入、专家审核、错误返工、合规风险或内容制作成本。
4. **为什么现在买**：说明现有工具的缺口，以及项目能带来的可衡量结果。

## 面试回答示例

不要只说：“我做了一个金融文档问答系统。”

应该说：

> 目标用户是每天处理年报和经营报表的研究员，真正的买单方通常是券商、银行或咨询公司的业务团队。它们愿意付费，不是因为多了一个聊天窗口，而是因为系统能减少人工翻表和重复核对，把数值结果连同来源一起交付，并降低错误数据进入报告的风险。当前版本还不是生产产品，但已经验证了数据链路、确定性计算和审计边界。

这类表述既说明商业价值，也不会把原型夸大成已经商业化的产品。
