# 社区图谱重构计划

> 状态：设计讨论稿，尚未实现
>
> 目标：将知识库图谱从人工分类主导的目录视图，逐步重构为“Markdown 页面底层实体 + 页面引用图 + 自动发现的社区高层图”。本文只记录计划、边界和待决策事项，不代表现有代码已经支持这些能力。

## 1. 背景与目标

当前知识库已经拥有页面、双链、项目标签、人工分类和动态图谱。人工分类适合当前维护者的知识背景，但不一定适合作为通用个人知识库工具的默认组织方式。新的方向是让知识结构从底层页面关系中自动形成：

```text
Markdown 页面实体
    ↓ 页面引用图
社区发现
    ↓ 页面集合聚类
社区实体节点
    ↓ 社区摘要与边聚合
社区总览图
```

社区的主要用途是分类和全局视野，而不是在当前规模下强行替代全文搜索的性能优化。精确搜索仍然可以直接命中 Markdown 页面；社区层主要帮助用户理解知识库整体结构，并从高层主题下钻到具体页面。

## 2. 核心概念

### 2.1 页面实体

每个纳入知识库的 Markdown 页面是底层图中的一个实体节点。页面文件是事实来源，社区数据、摘要和布局数据均属于派生数据。

页面节点至少保留：

- 文件路径和稳定页面 ID；
- 标题、页面类型和更新时间；
- 页面摘要、信度和现有标签；
- 入边、出边和所属社区信息。

知识社区发现的输入只包含知识页。工程/项目页、工程面试页和 MOC 页继续保留在各自现有视图中，不进入知识社区计算，也不作为知识社区间边的中继节点。这样，知识社区描述的是知识页之间的引用结构，而不是项目目录或导航结构。

### 2.2 页面边

第一版底层边严格只使用知识页之间的明确引用关系：

```text
页面 A [[引用]] 页面 B
→ A -> B
```

边保留方向，同时在需要展示关系强度时聚合反向引用。标签共现、项目归属和正文语义相似度均不参与社区发现，也不自动等同于明确引用边；它们不能悄悄改变事实关系图。

### 2.3 社区实体

社区是页面节点聚类后的派生高层实体，不是人工预先创建的文件夹，也不替代成员 Markdown 页面。

一个社区至少包含：

- 稳定社区 ID；
- 层级（一级主题或二级领域）和父社区 ID；
- 成员页面列表；
- 子社区列表（仅二级领域社区）；
- 社区名称；
- 一句话摘要和详细摘要；
- 内部页面数和内部边数；
- 代表页面；
- 与其他社区的连接；
- 稳定性、生成时间和生成版本。

社区描述的是“这个页面集合共同表达的知识”，而不是单纯复用某个已有标签。

### 2.4 社区间边

社区间边由底层页面边聚合产生。若存在：

```text
页面 A ∈ 社区 1
页面 B ∈ 社区 2
A -> B
```

则社区 1 与社区 2 之间产生一条跨社区边。边上可记录：

- 方向；
- 底层引用数量；
- 涉及的页面对；
- 聚合强度；
- 是否存在双向引用。

社区图本质上是底层页面图按社区划分进行收缩后的结果：

```text
页面图 G_page / 社区划分
→ 社区图 G_community
```

## 3. 目标图谱层级

社区层级采用递归收缩，而不是仅有一级页面集合：

```text
知识库根视图（不是社区）
    ↓
二级领域社区
    ↓
一级主题社区
    ↓
Markdown 知识页
```

一级主题社区由知识页图运行 Leiden 得到。将每个一级社区收缩为一个节点、以跨社区显式引用聚合为边后，可以继续运行 Leiden，形成更高层的领域社区。原始横向引用和跨社区边继续保留，不把真实网状关系强行改写为树。

层数不是预先固定为两层或三层，而由每一轮收缩后的图结构决定。实现上需要有保护性最大深度，防止异常输入无限递归；这个上限只是计算保险，不是对用户可见的知识层级承诺。

## 4. 社区发现计划

### 4.1 输入特征

第一版只使用知识页正文中解析到的 `[[双链]]`。每条引用构成一条有向页面边；双向引用在算法或可视化需要无向权重时可聚合为更强的同一对页面关系。除显式引用外，不引入标签、项目归属、标题/摘要/正文相似度等弱边。

### 4.2 社区发现算法

第一版采用 **Leiden**。输入是由显式引用边聚合得到的无向加权知识页图，原始有向边仍保留给页面关系和社区间边展示：

- 单向引用：无向页面对权重为 `1`；
- 双向引用：同一页面对权重为 `2`；
- 不使用标签、项目归属或语义相似度补边；
- 使用固定随机种子，保证同一输入可重复得到同一结果；
- 使用模块度目标函数的工程常用基线分辨率 `gamma = 1.0`。

`gamma = 1.0` 是第一轮试验的工程常用基线，不随每次页面变化自动调参。正式默认值应通过一次离线校准确定，再固定在算法版本中；只有人工验收确认社区明显过粗或过碎时，才讨论重新校准。

选择 Leiden 的原因是它适合加权关系图，并避免部分 Louvain 结果可能出现的社区内部不连通问题。现有 taxonomy 使用的 Louvain 仅作为历史动态分类实现，不复用为新的社区图算法。

### 4.3 层级边界与超参数校准

需要区分两类参数，不能把它们都归结为分辨率：

- **粒度参数**：Leiden 分辨率 `gamma`，决定每一轮更偏向合并还是拆分；以 `1.0` 为起点，在预先定义的有限候选区间中离线比较。
- **层级停止参数**：决定是否接受本轮得到的父社区，而不是继续向上收缩。

建议的校准流程是：对固定的知识页图，在相同随机种子和固定候选 `gamma` 集合下生成多套层级结果；比较后选择一套，并将所有值与算法版本写入派生数据。评价不以“社区数量最多”或“模块度最大”单独决定，而同时检查：

1. 同一输入、不同种子下的成员稳定性；
2. 页面小幅新增或引用小幅变更后的层级稳定性；
3. 社区内部显式引用强度相对于跨社区引用的分离度；
4. 是否产生过多单页、双页或只有一个子社区的伪层级；
5. LLM 是否能为每个候选社区给出彼此可区分、且能由成员页面支持的名称与摘要；
6. 人工抽样查看代表页面后，对归属是否可解释。

每一层接受为父层的最低条件需要单独配置：父社区至少包含两个子社区，达到最小后代页面数，子社区之间存在足够的聚合显式引用，并且本轮不是“全部合并为唯一根节点”或“所有节点保持单例”的无信息划分。任一条件不满足即停止向上收缩。

`gamma`、最小叶社区页数、最小父社区子社区数、最小后代页面数、跨社区聚合边阈值、最大保护深度和随机种子都属于版本化算法配置；具体数值在离线试验和人工查看结果后确定。

### 4.4 社区边界

需要明确：

- 最小社区规模；
- 孤立页面是否进入“未形成社区”集合；
- 小社区是保留、合并还是暂不展示；
- 桥接页面是否允许进入多个社区；
- 社区内部密度和跨社区边比例的最低质量阈值。

建议默认采用“一个主社区 + 若干跨社区关联”的模型：页面有一个主要归属，跨主题关系通过社区间边表达，不强行复制页面。

## 5. 社区稳定性

社区不能因为单个页面新增或一条边变化就频繁改名、换 ID 或大幅重排。需要设计：

- 基于成员重叠的旧社区与新社区匹配；
- 社区合并、分裂、消失和新增事件；
- 社区稳定 ID 和重定向；
- 最小变化阈值；
- 旧快照保留和回滚机制。

稳定性指标可包括：

- 成员重叠率；
- 社区边界变化率；
- 名称变化次数；
- 摘要变化幅度；
- 连续运行轮次。

如果新结果质量不足，系统应保留上一版社区快照，并明确标记本轮未发布原因。

## 6. 社区命名与摘要

### 6.1 摘要内容

社区摘要应回答：

- 这个社区主要讨论什么；
- 它包含哪些代表性页面；
- 页面之间有哪些共同关系；
- 它与哪些其他社区存在联系；
- 最近发生了什么变化。

### 6.2 生成方式

第一版由 LLM 生成社区节点的可读语义信息。Leiden 的结果只负责确定成员集合；LLM 不参与重新分配成员、不新增页面、不补造页面边，也不修改 Markdown 正文或既有标签。

这里的“摘要抽象程度”只影响社区节点的文字表达，不影响底层社区发现结果。即使 LLM 认为某个社区难以概括，也只能降低摘要置信度或使用降级文本，不能据此拆分、合并或否决该社区。

每次生成向 LLM 提供经过长度控制的、可审计的事实输入：

- 社区稳定 ID、成员数量和代表页面；
- 成员页面的标题、摘要、页面类型和必要正文摘录；
- 社区内部显式引用边；
- 与其他社区相连的页面对及其方向；
- 上一版名称、摘要和成员变化（若存在）。

LLM 返回受限的结构化结果：

- 简洁、可区分的社区名称；
- 一句话摘要和详细摘要；
- 代表页面与共同主题说明；
- 社区边界说明，即主要不包含什么；
- 生成置信度及无法可靠概括时的原因。

只在社区首次形成、成员或内部边超过变化阈值、或用户主动刷新时调用 LLM；相同输入哈希直接复用已有结果，避免不必要的请求和名称漂移。无论调用是否成功，都保留生成时间、模型/方式、输入页面版本、输入哈希和失败原因。

摘要失败时应有本地降级名称，例如由代表页面标题组合产生，不能让社区节点因一次 LLM 调用失败而消失。

### 6.3 摘要的抽象程度

摘要应描述“这个已确定的页面集合共同表达什么”，而不是逐页复述。抽象程度由社区节点所在层级和成员结构决定，但只用于组织文字：

- 页面集合较小或主题集中：摘要聚焦共同机制、问题或方法；
- 页面集合较大或内部存在多个明显脉络：摘要先给共同上位主题，再分条说明主要子脉络；
- 高层社区：摘要描述其子社区之间的共同领域和差异，不罗列所有底层页面；
- 无法形成可靠共同概念：保留社区节点，使用“由哪些主题连接而成”的结构性摘要，并明确低置信度。

LLM 输出应同时包含一条面向总览的短摘要和一份可下钻的详细摘要。短摘要回答“这个社区整体是什么”，详细摘要回答“它由哪些脉络组成、为何被视为同一集合、与相邻社区如何区分”。摘要不得凭空引入成员页面没有支持的新结论。

### 6.4 社区节点页

社区节点页是独立的派生说明页，存放在 `communities/`，不放入 `pages/`，也不参与下一轮知识页引用图解析，避免社区页中的成员链接反向污染底层图。

所有层级共用同一基础结构：稳定 ID、层级、父社区、名称、摘要、成员统计、跨社区边、变化记录和生成信息。内容按层级展开：

- 一级主题社区：主要脉络、代表知识页、内部显式引用、外部连接和知识边界；
- 二级领域社区：子社区、各子社区的职责、代表知识页、领域内跨子社区连接和领域边界；
- 界面使用“知识库根视图 > 二级领域社区 > 一级主题社区 > 页面”的面包屑下钻路径。

### 6.5 可审计性

用户应能从社区节点查看：

- 成员页面列表；
- 形成社区的主要页面边；
- 社区规模和稳定度；
- 摘要生成依据；
- 与上一版本的变化。

## 7. 图谱交互计划

### 7.1 默认总览

知识库图谱默认显示社区节点和社区间边，不直接展示全部 Markdown 页面。社区节点的视觉属性可以表示：

- 节点大小：成员数或重要性；
- 边粗细：跨社区引用强度；
- 节点标签：社区名称；
- 辅助信息：页面数、最近变化、稳定度。

### 7.2 社区下钻

点击社区后显示：

- 社区名称和摘要；
- 成员页面；
- 代表页面；
- 社区内部关系；
- 外部社区连接；
- 最近变化事件。

### 7.3 页面局部视图

点击页面后显示：

- 页面所属社区；
- 一跳或两跳引用邻域；
- 入边和出边；
- 跨社区引用；
- 跳转 Viewer 阅读页面。

页面局部视图不要求加载全库所有节点，以控制视觉密度和布局耗时。

### 7.4 人工分类视图

现有人工分类不作为默认图谱主视图。迁移期间保留只读兼容或调试入口，用于：

- 旧链接兼容；
- 对照社区发现结果；
- 检查自动社区是否出现明显错误；
- 迁移失败时降级。

## 8. 搜索关系

社区层主要服务分类和全局视野，不以当前规模下的搜索加速为主要目标。

建议采用：

```text
精确关键词命中
→ 直接返回 Markdown 页面

模糊问题或低质量命中
→ 补充匹配社区、社区摘要和代表页面
```

当前直接字符搜索、标题搜索、标签过滤和模糊匹配可以继续保留。社区摘要可作为后续的模糊检索兜底入口，但不应强制所有搜索先经过社区层。

## 9. 数据文件与派生边界

建议将真实数据和派生数据分开：

```text
pages/*.md                 真实知识实体
graph-data.json            页面级图谱派生数据
community-data.json        社区成员、摘要和稳定性
community-graph-data.json  社区级图谱派生数据
community-events.json      社区新增、合并、分裂和变化事件
```

具体文件名、是否合并为一个 JSON、是否生成可审计 Markdown 视图，需要在实现前确认。

社区计算不得直接改写页面正文、frontmatter 或人工标签。所有社区结果都应能够重新计算、比较和回滚。

## 10. 迁移顺序

1. 读取现有页面和双链，离线生成页面图基线。
2. 在不影响现有图谱的情况下生成候选社区。
3. 检查社区成员、边界、名称、摘要和跨社区边。
4. 并行保留人工分类图和社区图。
5. 在 Viewer/Graph 页面增加社区总览和下钻入口。
6. 观察实际使用后，再决定是否将社区视图切换为默认入口。
7. 最后再决定人工分类数据是长期保留、隐藏，还是仅作为迁移兼容层。

## 11. 测试与验收

需要覆盖：

- 页面节点和引用边生成正确；
- 社区成员集合完整且无非法页面；
- 社区间边聚合方向、数量和强度正确；
- 相同输入重复运行结果稳定；
- 页面少量变化不会造成社区全面重排；
- 社区合并、分裂、新增和消失事件可审计；
- 摘要失败时有降级内容；
- 社区节点可下钻到页面；
- 页面可返回社区总览；
- 旧人工分类入口和旧链接不被意外破坏；
- 大图默认不加载全部页面节点，局部展开性能可接受。

## 12. 待讨论与待确认

以下问题确认前不应进入正式实现：

1. 页面是“一个主社区 + 关联社区”，还是允许真正的多社区归属。
2. 知识页范围的具体判定规则：现有概念页之外的特殊知识页是否纳入；工程/项目页、工程面试页和 MOC 页已明确不纳入。
3. 用于校准 `gamma` 和层级停止条件的候选区间、评价样本和通过标准。
4. 社区摘要和社区图数据是否提交 Git，还是作为可重建缓存。
5. 社区总览是否直接替代现有人工分类作为默认图谱入口。
6. 人工分类数据最终是保留为兼容层，还是在迁移完成后移除。

## 13. 明确不在本计划中的内容

- 不把工程/项目页、工程面试图谱和知识库社区图合并；
- 不引入多用户、账号、云同步或在线协作；
- 不要求把正文拆成大量独立实体节点；
- 不让社区算法直接修改 Markdown 页面；
- 不为了社区层而放弃现有直接字符搜索；
- 不在细节未确认前修改现有生产图谱和人工分类数据。
