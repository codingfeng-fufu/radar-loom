# NarraGraph（忆绘）

## 一句话介绍

NarraGraph 是一个口述人生故事画册生成系统：从文本输入中抽取人物、场景、道具和视觉母题，生成章节脚本、角色设定图、逐章水彩插画，最终排版导出 PDF。

## 30 秒回答

我做了一个把口述人生故事生成成水彩小册的多模态应用。输入是一段 txt 口述稿，系统先用文本模型生成五幕人生章节和视觉知识库，再为不同年龄阶段生成角色设定图，正文插画通过参考设定图保持人物身份一致，最后用 PIL 排版封面、标题、旁白和页码并导出 PDF。系统不是一次调用文生图 API，而是有分阶段 pipeline、manifest、QC 报告、离线 review 和可恢复的 CLI/Web 工作流。

## 1. 项目背景

### 要解决的问题

- 长故事需要压缩成有限章节，但不能变成简单时间流水账。
- 图像模型容易在不同章节改变人物年龄、服装、脸型和视觉风格。
- 生成的原始图片还不能直接交付，需要统一排版、封面和 PDF 输出。
- 外部模型调用可能失败或成本较高，需要 mock 模式、阶段重跑和产物记录。

### 产品目标

跑通“口述文稿 -> 五幕章节脚本 + 视觉知识库 -> 角色设定图 -> 逐章插画 -> 排版成册 -> PDF”的完整闭环。

## 2. 系统整体架构

## 2A. 谁使用、谁买单

直接用户是想保存家庭记忆的个人和家庭，也可以是文旅、影像、出版机构的内容客户；买单方主要是消费者，或提供定制纪念品服务的机构。购买理由是把口述材料变成个性化画册，替代人工采访整理、插画创作和排版交付的部分成本。当前产品仍需通过样本故事、生成成本、人工复核时间和用户付费意愿验证商业模型。

```text
口述/自述文稿
      |
      v
文本处理：五幕章节 + 人物/场景/道具/motif
      |
      v
JSON Knowledge Store + prompt builder
      |
      +--> 分年龄阶段角色设定图
      |
      +--> 章节插画生成（引用角色设定图）
      |
      v
PIL 排版：标题 + 旁白 + 页码 + 封面拼贴
      |
      v
PDF + manifest.json + qc_report.json + review contact sheets
```

Web 版本由 FastAPI 服务、SQLite 数据层、worker/state machine 和 Vite 前端组成；CLI 支持按阶段运行和复用已有产物。

## 3. 我的个人贡献

- 设计从故事文本到画册 PDF 的端到端 pipeline 和阶段化 CLI。
- 设计五幕脚本、角色阶段、视觉 motif 和 `identity_anchor` 等中间结构。
- 实现知识存储、prompt 构建、角色设定图、图像生成、PIL 排版和 PDF 导出。
- 实现 manifest、QC 报告、离线验证、接触表和阶段恢复机制。
- 参与 Web 产品的项目、文件、审核、反馈、成本和 worker 状态管理。

## 4. 核心技术实现

### 4.1 故事结构化而不是直接生成图片

文本模型先抽取章节、因果连接、情绪强度、镜头设计、时代和角色阶段，再把人物、场景、道具与 motif 写入 JSON 知识库。这样图像 prompt 不是直接从原始长文本拼接，而是由结构化故事状态生成。

### 4.2 角色身份一致性

系统为不同年龄阶段先生成中性背景的角色设定图，正文插画只引用对应阶段的设定图，并在 prompt 中固定 `identity_anchor` 和阶段外貌描述。默认不把上一章叙事图作为参考，避免构图复制和错误细节跨章节传播。

### 4.3 视觉母题追踪

`motifs` 用于记录麻绳、铺盖卷、手上的茧、砖墙、老槐树等跨章节视觉线索。章节生成时把对应 motif 注入 prompt，QC 再检查这些元素是否落地，使画册具有前后呼应而不是一组互不相关的图片。

### 4.4 产物、排版和可复查性

每章同时保存原始图和排版页，manifest 记录 prompt、参考图、标题、旁白、PDF 路径；`qc_report.json` 记录镜头重复、motif 落地和人工复核清单。PIL 负责正文底部渐变遮罩、章节标题、旁白、页码和非对称封面拼贴。

### 4.5 阶段化执行与 Web 工作流

CLI 将分析、角色设定图、插画、排版、PDF 导出和 QC 拆成独立阶段，已有产物默认复用，单个阶段失败时可局部重跑。Web 版本通过 worker 和 state machine 管理项目状态、反馈、审核、文件和成本信息，Mock 模式不需要真实模型 key。

## 5. 最难的问题

### 难题一：如何把长人生故事压缩成有因果的章节

不只按时间切段，而是要求章节携带 `causal_link`、`emotion_intensity`、`shot_design`、`era` 和 `character_stage`。这样每一章既有叙事作用，也有可执行的画面设计。

### 难题二：如何避免角色跨章节漂移

角色身份被拆成年龄阶段设定图、identity anchor 和结构化外貌描述三层约束；正文图只参考对应阶段设定图，生成后通过 contact sheet 和 QC 报告进行人工复核。

### 难题三：如何控制生成成本和失败恢复

文本分析、角色设定、插画和排版分阶段持久化。manifest 记录每次生成参数，cost tracker 记录成本，已有产物可复用，避免一次小修改重新生成整本画册。

### 难题四：视觉质量如何变成可检查结果

系统不声称 QC 能完全理解审美，而是先把可自动检查的部分结构化：镜头重复、motif 落地、文件完整性、PDF 路径和 manifest 对应关系；主观质量留给 contact sheet 和人工复核。

## 6. 项目结果与量化验证

### 可交付产物

- 每个故事生成 6–9 个阶段章节的故事小册结构。
- 每章包含排版完成的 PNG、标题、旁白和页码。
- 输出封面拼贴、最终 PDF、`manifest.json` 和 `qc_report.json`。
- 提供 CLI 完整运行、分阶段运行、离线 validate 和 review contact sheet。
- Web 版本提供项目、文件、图谱、反馈、审核、成本和 worker 状态接口。

### 工程验证口径

项目包含文本 schema、角色设定、候选评分、图片生成策略、PDF 导出、QC、状态机、worker、认证、文件隔离和多用户隔离测试。当前 README 没有给出统一的端到端图像质量分数，因此面试时应展示具体生成画册和 QC 报告，不虚构“角色一致性准确率”等指标。

### 已知边界

当前知识存储仍是简化 JSON，尚未升级为真正的 NetworkX/Neo4j 图谱；尚未实现图谱与视觉常识的双向校验，也没有本地 4090 离线模型分支。外部文本和图像 API 的可用性、成本与生成质量会影响最终结果。

## 7. 现场演示顺序

1. 上传或选择一段口述故事文本。
2. 展示五幕章节、人物阶段和视觉 motif。
3. 展示角色设定图，再查看对应章节插画。
4. 展示排版页、封面拼贴和最终 PDF。
5. 打开 manifest，说明每页 prompt 和参考图来源。
6. 打开 QC 报告和 contact sheet，展示如何做自动检查与人工复核。

## 8. 可能追问

### 为什么要先生成角色设定图？

直接让每章图像模型重新理解人物容易产生身份漂移；先建立阶段设定图，再作为参考能把人物约束固定下来。

### 为什么不直接把全文放进图片 prompt？

全文过长且叙事重点不稳定。先抽取章节、角色、场景和 motif，能降低 prompt 噪声并支持按阶段重跑。

### 这是知识图谱系统吗？

目前是视觉知识库和 JSON 结构，不是完整图数据库；项目预留了升级到 NetworkX/Neo4j 的接口，当前重点是可交付的故事生成闭环。

### 当前限制是什么？

视觉质量仍需人工审核，真实模型调用依赖外部 API，复杂故事的因果抽取和长期人物一致性仍有提升空间。

## 9. 1 分钟总结

忆绘的难点不是调用一次文生图 API，而是把非结构化人生故事转成稳定的中间表示，再用角色设定、视觉母题和阶段化 pipeline 约束多章生成，最后交付可阅读、可复查的 PDF 画册。我重点做的是这条从文本理解、知识组织、图像生成到排版验收的完整工程链路。
