# 文本蕴含与自然语言推理 NLI

## 核心内容

### 第0层：本体定义（基础）

NLI（自然语言推理，又称文本蕴含）是给定两个句子，判断它们逻辑关系的任务：
- **前提（Premise）**：证据、来源文本、已知事实
- **假设（Hypothesis）**：待验证的陈述、抽取出的三元组、生成的答案

输出是三分类：
1. **蕴含**：如果前提为真，假设必然为真
2. **矛盾**：如果前提为真，假设必然为假
3. **中立**：前提为真时，假设可能真也可能假，无法判断

**两个反直觉但极其重要的关键性质：**
1. **NLI 只关心逻辑关系，不关心前提本身对不对**——前提说"太阳是方的"，假设说"太阳不是圆的"，这仍然是蕴含。✨ **这就是 TripleChecker 的核心设计哲学：我不判断这条知识"客观上对不对"，我只判断它"有没有被来源文本支持"**。
2. **NLI 是单调的**——增加新前提不能反转已有判断。如果 P1 蕴含 H，那么 P1 + P2 也应该蕴含 H。这是多跳路径验证的理论基础。

### 第1层：核心定位（30秒定调）

**我对NLI的定位：它是大模型阶段所有验证类问题的通用形式化框架。**

### 四大技术路径演化
1. **规则与特征工程阶段（2014年前）**：人工写规则、基于WordNet的同义词匹配，泛化能力差
2. **深度学习阶段（2014-2018）**：SNLI数据集发布，ESIM等基于LSTM的模型准确率达到88%
3. **预训练语言模型阶段（2018-2023）**：BERT/RoBERTa在MNLI上微调，准确率突破92%。**这是TripleChecker用的方案**——110M参数，GPU每秒跑100+样本，性价比最高
4. **大模型阶段（2023至今）**：三种主流路径——直接用大模型zero-shot判断、大模型标数据蒸馏小模型、多个NLI集成投票。我选的是蒸馏路线，成本低、可控性强

### 六大变种任务（本质全是NLI换马甲）
- 事实验证 → 多前提NLI
- 归因评测 → 答案vs原文的NLI
- 引用精度 → 引用句vs原文的NLI
- 矛盾检测 → 二分类NLI
- 三元组分类 → 三元组转句子做NLI
- 问答验证 → 问题+答案vs原文的NLI

**一句话总结**：你看到的所有"LLM幻觉检测"，扒开来看本质全是NLI。

## 和我的项目的关系

NLI是我整个技术栈的最底层基石，所有上层能力都建立在它之上：

1. **[[TripleChecker]]核心引擎**：把三元组转成自然语言假设，来源文本当前提，NLI验证这条三元组是不是幻觉——把KG抽取准确率从75%拉到92%
2. **[[EvidenceFirst]]路径验证**：不做整句NLI，把推理路径拆成多跳，每一跳单独验证——只要有一跳不成立，整条路径就不成立
3. **[[Graph Fusion 图融合]]多源投票**：三个来源分别和目标事实做NLI，2票以上才算高置信度——人工审核量减少70%
4. **[[FinGraph 财务知识图谱]]领域适配**：通用NLI在财务场景准确率只有78%，用qwen-plus标5000条领域数据蒸馏后，直接升到92%，达到金融分析师级别

### 核心设计选择
我没有用LLM直接做judge，而是用「大模型标数据 + 小NLI上线」的组合——
- 避免了「用大模型检验大模型」的循环依赖
- 速度快100倍，成本低100倍
- 输出是0-1连续置信度，方便做分层阈值

## 面试回答框架（五层递进）

1. **基础定义**：NLI是前提(P)到假设(H)的三分类——蕴含/矛盾/中立，只关心逻辑关系不关心前提本身对错，这是理论基础
2. **定调**：NLI不只是一个三分类任务，它是大模型阶段所有验证问题的通用框架
3. **讲选择**：四个技术路径我为什么选了「大模型蒸馏小NLI」——讲清楚trade-off（避免循环依赖、速度快100倍成本低100倍、输出可控）
4. **讲四个落地实例**：TripleChecker分层置信度、EvidenceFirst路径级NLI、Graph Fusion多源投票、FinGraph领域蒸馏，每个一句话讲结果
5. **拔高**：现在很多人做KG还在研究怎么把链接预测准确率提1个点，但真正的问题是——你根本不知道LLM抽出来的三元组本身对不对。所有上层的GNN、路径推理、问答，都必须建立在底层每一条三元组都经过NLI验证这个基础上，否则全是空中楼阁。
