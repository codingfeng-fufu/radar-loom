# 链接预测 Link Prediction

## 核心内容

链接预测是知识图谱补全最常见的子任务，目标是预测两个实体之间是否存在某种特定关系，或者预测给定头实体和关系的尾实体。本质上就是补全图谱里缺失的边。

四大实现路径：
1. **表示学习**：TransE 平移假设 $h+r\approx t$，后续变种 TransH/TransR/RotatE 解决对称/反对称关系问题。优点是效果稳定，缺点是嵌入完全不可解释，工业界很少真用。
2. **规则学习**：AMIE算法挖掘Horn规则，如「A的父亲是B，B的父亲是C → A的祖父是C」。优点100%可解释，缺点覆盖率低。LLM普及后这类方法的研究明显减少。
3. **GNN**：消息传递范式聚合邻居信息，RGCN专门为异构图设计。优点是能利用图结构信息，缺点是训练推理慢，百万节点以上大图提升有限。
4. **大模型方法**：2024年以后逐渐成为主流，分两种路线——直接让LLM预测实体间的关系，或者用NLI只做验证不做预测。

五大变种任务（本质都是链接预测换马甲）：KG补全、实体对齐、实体消歧、三元组分类、冲突检测——核心都是算两个实体之间有没有某种边。

## 和我的项目的关系

我做了三个项目后发现：**学术研究里的链接预测，和工业落地里的链接预测，几乎是两个完全不同的问题**——
1. 目标函数不一样：学术界比谁排得高，工业界比谁删得准
2. 可用信息不一样：学术界只能看到图结构，工业界有原始文本，根本不需要猜，直接去原文里验证就行
3. 错误代价不一样：学术界排错一个MRR降0.02，工业界错一个关键三元组就是生产事故

我的三个实践改造：
- [[TripleChecker]]：从排序问题改成二分类问题——不预测"哪个对"，只判断"这个对不对"，准确率从70%升到92%
- [[EvidenceFirst]]：从预测改成验证——不猜"哪些实体相关"，直接BFS搜"哪些实体真的连通"，有路径100%正确，没路径也不瞎编
- [[Graph Fusion 图融合]]：从单源相似度改成多源分层验证——先过TripleChecker过滤，再规则对齐，最后LLM验证，人工审核量减少70%

核心洞察：现在LLM太能无中生有了，我们不需要另一个模型来生更多边，我们需要一个模型来帮我们删掉错的边。
