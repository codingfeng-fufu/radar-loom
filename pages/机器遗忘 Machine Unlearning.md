# 机器遗忘 Machine Unlearning

## 核心内容

机器遗忘(Machine Unlearning)是指在不重新从零训练的前提下,让已训练好的模型精确去除特定训练样本(或某类知识、某个用户数据)的影响,使遗忘后的模型行为等价或近似等价于"从未见过这些数据"训练出来的模型。核心驱动力有四:GDPR / 个人信息保护法赋予的被遗忘权、版权数据下架要求、有毒/有害数据(偏见、隐私泄露、越狱示例)的事后清理、以及后门/投毒攻击的定向消除。

方法上分三条路线:
- **精确遗忘(Exact Unlearning)**:代表是 SISA(Sharded, Isolated, Sliced, Aggregated),把数据分片独立训练子模型,遗忘某样本时只需重训受影响的分片,拿"可证明等价于重训"当理论保证,代价是训练架构必须提前配合。
- **近似遗忘(Approximate Unlearning)**:通过影响函数(Influence Function)、Fisher 信息、梯度上升(Gradient Ascent)、参数扰动等,在不重训的情况下把目标样本的影响从权重里"反向剥离"。速度快、无需改训练流程,但没有严格等价保证,通常需要配合"成员推断攻击(MIA)不能区分"这类经验指标来评估。
- **LLM 场景专用**:参数量太大 SISA 不可行,主流做法是 Task Vector(算出"包含目标知识"和"不包含"两版权重差再做减法)、RLHF/DPO 反向对齐把不想要的行为压下去、以及针对特定事实的定位-编辑(如 ROME / MEMIT 的反向使用)。代表评测是 TOFU benchmark 和 "Who's Harry Potter" 论文。

评测三个维度必须同时看:**遗忘充分性**(目标数据是否真被遗忘,常用 MIA、精度掉零、KL 散度)、**模型效用保持**(其他任务不能被破坏)、**效率**(时间/算力相对完整重训的开销)。三者存在明显 trade-off,当前没有方法在三者上同时占优。

## 和我的项目的关系

- **EvidenceFirst**:强相关。被遗忘权要求"能证明数据已被删除",这恰好是 EvidenceFirst 强调的可审计性/溯源能力——遗忘操作本身需要生成可验证的证据链(哪条数据、哪次遗忘、遗忘后模型指纹),配合 [[SHA-256 产物指纹]] 就是天然的合规产物。
- **TripleChecker**:中等相关。当质量评估判定某条三元组错误或过时,除了在 KG 层删除,还需要考虑下游 LLM 是否已经"记住"了这条错误知识——这就是 LLM unlearning 的场景。可以作为 TripleChecker 的一个下游能力方向。
- **GSAD**:弱相关。动态知识撤回与时序演化中,过期知识的"遗忘"是天然需求,但 GSAD 更偏检索层而非参数层,通常靠 RAG 换库解决即可,不一定要走 unlearning。
- **ChronoLink / CoMaGRAG**:暂无直接关联。
