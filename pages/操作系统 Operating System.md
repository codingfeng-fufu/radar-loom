# 操作系统 Operating System

## 核心内容

操作系统（Operating System, OS）是管理计算机硬件、为应用程序提供运行环境与公共服务的系统软件。它位于硬件与应用之间，是所有其他软件运行的基础——没有 OS，每个程序都要直接驱动磁盘、键盘、网卡并自备 CPU 调度逻辑。

教科书通常给出两个互补的视角（Tanenbaum《Modern Operating Systems》、Silberschatz《Operating System Concepts》）：

1. **自顶向下——扩展机器（Extended Machine / Abstraction）**：硬件本身的接口（寄存器、中断、DMA、原始磁盘扇区）复杂且难编程。OS 把这些丑陋的底层细节封装成清晰、易用、可移植的抽象：文件代替磁盘扇区、进程代替 CPU 时间分片、虚拟内存代替物理 RAM、套接字代替网络硬件。程序员面对的是 OS 提供的"虚拟机"，而非裸机。
2. **自底向上——资源管理者（Resource Manager）**：计算机的 CPU、内存、磁盘、网卡、I/O 设备都是有限资源，多个进程在同时竞争它们。OS 在竞争者之间分配、调度、隔离资源，保证互不干扰、公平且高效。现代计算机同时运行数十上百个进程，没有 OS 的资源管理就无法并发。

### 核心功能

| 功能 | 职责 | 典型机制 |
|------|------|---------|
| **进程管理** | 创建/终止进程、线程调度、进程间通信、同步与死锁处理 | PCB、调度器、信号量、管程 |
| **内存管理** | 跟踪内存使用、分配/回收、地址隔离、虚拟内存 | 分页、分段、TLB、页面置换（如 [[LRU 缓存替换 Least Recently Used]]） |
| **文件系统** | 持久化存储的组织与访问、目录、权限 | FAT、ext4、NTFS、日志、缓存 |
| **I/O 与设备** | 屏蔽设备差异、统一驱动模型、中断与 DMA 处理 | 设备驱动、中断处理、块/字符设备 |
| **网络** | 协议栈、套接字抽象、数据收发 | TCP/IP、socket、缓冲区管理 |
| **安全与保护** | 用户认证、访问控制、权限隔离、系统调用过滤 | 用户/内核态、权限位、capability、沙箱 |
| **用户界面** | shell、图形界面、系统工具 | CLI、GUI、系统调用接口 |

### 关键抽象

操作系统最深刻的贡献是若干经久不衰的**抽象**，它们把硬件的复杂性隐藏在简洁接口之后：

- **进程（Process）**：对"正在运行的程序"的抽象。一个进程拥有独立的地址空间、打开的文件、寄存器状态等资源；OS 通过时分复用让多个进程"看起来"同时运行。进程是资源分配的基本单位，**线程（Thread）** 是 CPU 调度的基本单位。
- **虚拟内存（Virtual Memory）**：每个进程看到一片连续、私有的地址空间，由 OS 映射到物理内存（甚至磁盘上的交换区）。这带来了三大好处：进程间隔离、地址空间大于物理内存、简化程序链接与加载。分页机制下地址转换由 MMU 硬件完成。
- **文件（File）**：对持久存储的抽象，把磁盘的扇区序列组织成命名、可增长、带权限的字节流，屏蔽了块设备的物理细节。
- **系统调用（System Call）**：用户程序请求 OS 服务的受控入口。应用不能直接操作硬件，必须通过 syscall 陷入内核态，由 OS 代为执行并返回结果。常见的系统调用包括 `fork/exec`、`open/read/write`、`mmap`、`socket` 等。

### 用户态与内核态（Dual-Mode Operation）

现代 CPU 至少提供两种执行模式：

- **内核态（Kernel Mode）**：可执行所有指令、访问所有硬件与内存。OS 内核运行于此。
- **用户态（User Mode）**：只能执行非特权指令、只能访问本进程地址空间。应用程序运行于此。

模式切换通过**陷阱（trap）/系统调用**发生：应用执行特殊指令（如 x86 的 `syscall`、ARM 的 `svc`）触发受控异常，CPU 切换到内核态并跳转到 OS 预设的处理函数；OS 检查参数合法性、执行服务、返回结果后切回用户态。这种双态设计是 OS 实现保护与隔离的硬件基础：用户程序无法直接绕过 OS 访问硬件或其他进程内存。中断、异常、系统调用与上下文切换的完整流程见 [[操作系统运行机制 OS Runtime Mechanisms]]。

### 内核架构

"内核"（kernel）是 OS 中常驻内存、运行于内核态的核心部分。内核如何组织内部服务，有三种主流架构：

**1. 宏内核（Monolithic Kernel）**

所有 OS 服务（进程调度、内存管理、文件系统、设备驱动、网络栈）都运行在内核态，共享同一地址空间，以直接函数调用互相通信。优点是**性能高**（无切换开销）；缺点是任何组件的 bug 都可能导致整个系统崩溃，且模块间耦合强。代表：**Linux**、FreeBSD、Solaris、早期 Unix。Linux 通过可加载内核模块（LKM）在运行时动态增删驱动，获得了一定模块化能力，但架构上仍是宏内核。

**2. 微内核（Microkernel）**

内核只保留最基本的机制：地址空间管理、线程/进程调度、进程间通信（IPC）。其他服务——文件系统、设备驱动、网络栈——全部作为用户态的"服务器进程"运行，客户端通过 IPC 请求服务。优点是**隔离性强、可扩展性好、可维护性高**（驱动崩溃不会拖垮内核）；缺点是频繁的 IPC 上下文切换带来性能开销。代表：**Minix**（Tanenbaum 开发，用于教学）、QNX（广泛用于嵌入式与汽车）、L4、Mach。

1992 年著名的 **Tanenbaum–Torvalds 辩论**即围绕微内核 vs 宏内核展开：Tanenbaum 认为宏内核过时、微内核才是未来；Torvalds 则为 Linux 的宏内核实用主义辩护。三十年后，宏内核（Linux）在服务器与移动领域占据主导，但微内核思想深刻影响了 QNX、seL4（形式化验证的高安全内核）以及混合内核设计。

**3. 混合内核（Hybrid Kernel）**

在微内核结构基础上，把部分关键服务（如文件系统、网络栈）放回内核态运行以获得接近宏内核的性能，同时保留模块化设计。严格来说，混合内核在结构上类似宏内核，但借鉴了微内核的分层与服务分离思想。代表：

- **Windows NT**（由 Dave Cutler 领导设计，受 VMS 和 Mach 影响）：底层是类似微内核的 Kernel 层（调度、中断），上层是 Executive（对象管理、I/O、进程、内存），整体运行于内核态。
- **XNU**（macOS/iOS）：结合 CMU Mach 微内核与 FreeBSD 的 BSD 层，加上 I/O Kit 驱动框架。Mach 负责任务、虚拟内存、IPC，BSD 提供 POSIX 接口与进程模型，二者共享内核地址空间。
- BeOS、DragonFly BSD。

| 特性 | 宏内核 | 微内核 | 混合内核 |
|------|--------|--------|---------|
| 性能 | 最高（直接调用） | 较低（IPC 开销） | 接近宏内核 |
| 稳定性 | 较低（一处崩溃全挂） | 高（服务隔离） | 中等 |
| 可扩展性 | 差（需重编译/重启） | 好（加用户态服务） | 中等 |
| 代码量 | 大 | 内核核心小 | 中到大 |
| 典型代表 | Linux、FreeBSD | Minix、QNX、L4、seL4 | Windows NT、XNU |

### 操作系统的主要类型

按应用场景与设计目标，OS 可分为：

- **批处理系统（Batch）**：早期大型机 OS，一次装入一批作业顺序执行，无交互。代表：OS/360。
- **分时系统（Time-sharing）**：多用户通过终端同时交互，CPU 在任务间快速切换。代表：Multics、Unix。
- **桌面/通用 OS**：面向个人计算机，强调交互体验与软硬件兼容性。代表：Windows、macOS、Linux 桌面版。
- **服务器 OS**：面向网络服务，强调稳定性、并发、吞吐。代表：Linux 服务器版、Windows Server、FreeBSD。
- **实时操作系统（RTOS）**：保证任务在确定的时间内完成（硬实时/软实时），用于工业控制、汽车、航空。代表：VxWorks、QNX、FreeRTOS、RT-Linux。
- **嵌入式 OS**：资源受限设备上的专用 OS。代表：嵌入式 Linux、Zephyr、Contiki。
- **分布式 OS**：管理多台机器、对用户呈现为单一系统。代表：Amoeba、Plan 9。
- **移动 OS**：手机/平板，强调功耗、触摸交互、应用沙箱。代表：Android（Linux 内核）、iOS（XNU）。

### 一个最小的认知模型

可以把 OS 理解为三层：

```
应用程序 (用户态)
─────────────────────  系统调用接口 (syscall)
操作系统内核 (内核态)
  ┌───────────────────────────────┐
  │ 进程 │ 内存 │ 文件 │ I/O │ 网络 │ 安全 │
  └───────────────────────────────┘
─────────────────────  硬件抽象层/驱动
硬件 (CPU、内存、磁盘、设备)
```

应用通过系统调用进入内核，内核通过驱动操控硬件；所有并发、隔离、抽象都发生在中间这一层。

### 常见误区

- **OS 就是内核**：不严格。OS 是整个系统软件包，包括内核、系统库、shell、工具、守护进程；内核只是其中运行于特权态的核心。
- **操作系统就是 Linux/Windows**：这些是具体实现，概念上 OS 还包括 RTOS、嵌入式 OS、分布式 OS 等多种形态。
- **宏内核已经过时**：Linux 在服务器、移动（Android）、超算领域占绝对主导；微内核在安全关键与嵌入式领域有其位置，但"微内核必然取代宏内核"的预测并未发生。
- **系统调用就是函数调用**：系统调用会触发用户态到内核态的模式切换（trap），开销远大于普通函数调用，涉及寄存器保存、权限检查、参数校验与上下文切换。
- **虚拟内存让内存变大**：虚拟内存提供的是大于物理内存的地址空间，但通过换页到磁盘实现，访问换出的页会触发缺页异常，代价很高；它不是"免费的内存"。
- **64 位系统一定比 32 位快**：64 位的主要优势是更大的地址空间与更多寄存器，代码体积也可能增大；性能取决于具体工作负载。
